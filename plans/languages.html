uscope plan

Odin, Fortran, D, Nim, and Ada

uscope debugs C, C++, Rust, Go, and Zig. Five more languages compile to native code with DWARF that uscope can already partly read: Odin, Fortran, D, Nim, and Ada. Supporting them widens who can use uscope. More importantly, their compilers describe programs in ways ours do not, and every place where uscope quietly assumed C is a bug that can also hide in the languages it already supports.

Summary

Each language gets one commit, so its cost is visible on its own: its toolchain in the flake, how uscope recognizes its units, whatever its values need from the type layer, a small views file for its most common library types, and a few fixtures with high-value tests. General bugs the new compilers expose are fixed in commits of their own, each with a test written to fail first, so they can be kept whichever languages stay.

Every toolchain must come from the pinned flake. A language whose fixtures cannot be built hermetically is not supported.

The first probes, one small program per language, already found real bugs: arrays in Fortran and Ada show one element too many, because uscope assumes C's lower bound of 0 where those languages' default is 1; nameless artificial variables, which gfortran emits, are listed as malformed; and Fortran's assumed-shape and allocatable arrays and its strings are not read at all.

Languages considered

What every native language gets without any work: breakpoints, stepping, unwinding, and values shown as raw records, as long as the compiler emits reasonable DWARF. What a language costs beyond that depends on how much of the following it needs: recognizing its units, demangling its names, presenting its built-in types (slices, strings, maps, tagged unions, optionals), its expression syntax, and its runtime (panics, green threads).

LanguageDecisionWhy
OdinSupportThe audience closest to Zig's and Jai's: games and low-level systems. LLVM backend, reasonable DWARF, in nixpkgs. Strings, slices, dynamic arrays, any, and unions are cheap; maps' layout is not described by DWARF and is internal to the runtime.
FortranSupportA large HPC audience, mostly served by GDB. Its arrays use DW_AT_data_location, DW_AT_allocated, and bounds computed by DWARF expressions, which makes gfortran an excellent check of uscope's DWARF handling even if few Fortran users arrive.
DSupportMature DWARF with its own DW_LANG_D, a real user base, and a mangling scheme of its own. LDC is in nixpkgs; GDC is not.
NimSupportCompiles through C, so its units are C with #line mappings back to .nim files and C++-style mangled function names: a test that source mapping and naming hold when the C file is not the real source.
AdaSupportNearly free to compile, since GNAT is GCC, and used seriously in safety-critical work. Its arrays have arbitrary bounds and its unconstrained arrays are fat pointers.
C3LaterThe same shapes as Odin (LLVM, slices, optionals, any), so cheap once Odin works, but a very small user base.
CrystalLaterLLVM and DWARF, and fibers that would fit the task model built for goroutines and tokio. A small audience.
JaiNot nowIts users are the most likely to want uscope, but its compiler cannot come from the flake, so its fixtures cannot be hermetic. If it is ever done, it is an opt-in local recipe outside every gate, which fails rather than skips when the compiler is missing, with nothing checked in that names the compiler.
SwiftNoReal Swift debugging relies on its reflection metadata and async runtime, not on DWARF alone: a project of its own.
Haskell, OCamlNoTheir DWARF is mostly line tables and unwind information with few or no variables, and their execution models do not map onto ordinary frames.
Julia, MojoNoThey compile at run time in practice, which needs the GDB JIT interface: a different feature from language support.
Hare, VNoHare's backend emits almost no debug information; V compiles through C and has a small audience.

What support means

The architecture already says where each piece belongs: language facts are normalized at the debug-information boundary, presentation of library types is views, and the evaluator stays language-neutral.

LayerWorkRule
RecognitionA SourceLanguage for each, from DW_AT_language, or from the producer or unit name where a compiler says C (Odin says C99; Nim's units are clang's or GCC's C).A unit whose language cannot be proven stays what its DWARF says.
Language rulesThe DWARF defaults that depend on the language, such as an array's lower bound, read from the unit's language.A language whose default is unknown has none: the type says so instead of assuming C's.
ValuesBuilt-in types that every program uses and that DWARF describes structurally: Odin's and D's slices and strings, Odin's unions, Fortran's and Ada's arrays and strings.Recognized by shape and language at the boundary, never by guessing; a layout that does not match stays raw, with the reason.
ViewsOne built-in views file per language for its most common library types: dynamic arrays, maps where their layout can be proven, unbounded strings.Every view binds in some fixture, and every view refuses a value it cannot prove whole.
NamesPatterns that name each language's types, and function names as the language writes them where that is cheap and exact (Nim's are Itanium-mangled).No demangler is guessed at; an unrecognized name is shown as stored.
RuntimeOut of scope: no panic or exception stops, no green threads, no expression syntax per language.

The five

odin

Odin

nixpkgs odin dev-2026-05, LLVM backend. Units say DW_LANG_C99 with producer odin; type names are package::Name with arguments in parentheses, as runtime::Maybe(T:$int).

  • Slices and strings are {data, len}; dynamic arrays add cap and an allocator.
  • A union is a DWARF union whose tag member follows the payload, and whose variants are v1…vN, tag 0 being nil.
  • cstring is a pointer to char that should read as text.
  • Maps are a single tagged pointer into cells laid out by the runtime, which DWARF does not describe.
fortran

Fortran

nixpkgs gfortran 15.2, the same GCC as the C fixtures. Units say DW_LANG_Fortran08.

  • Arrays default to a lower bound of 1.
  • Assumed-shape and allocatable arrays are descriptors: DW_AT_data_location, bounds and strides as expressions over DW_OP_push_object_address, and DW_AT_allocated.
  • Character variables of deferred length are DW_TAG_string_type with a length in another variable.
  • The program's body is MAIN__, marked DW_AT_main_subprogram; main is gfortran's wrapper.
d

D

nixpkgs ldc 1.41 (LLVM 18). Units say DW_LANG_D.

  • Arrays and strings are slices laid out {length, ptr}, length first.
  • Associative arrays are an opaque pointer to the runtime's table, which DWARF does not describe.
  • The program's body is named D main; druntime has no debug information, so its frames show D-mangled symbols.
nim

Nim

nixpkgs nim 2.2.4, compiling through the flake's C compilers. Units are C named …/@mmodule.nim.c.

  • Function names are Itanium-mangled, as _ZN3nim4mainE.
  • Strings are NimStringV2 {len, p} with the bytes in p->data; sequences are tySequence__hash {len, p}, one type per element type.
  • Locals carry numeric suffixes (s_1), and Nim's own temporaries are listed beside them.
  • Enums are typedefs of integers (typedef NU8 tyEnum_Color__hash). Their enumerators' names are in no debug information, only in the code of the $ Nim generates, so an enum shows as its number (see Deferred).
ada

Ada

nixpkgs gnat 15.2. Units say DW_LANG_Ada95; the runtime's C units say C11.

  • Arrays have any bounds, and default to a lower bound of 1.
  • Unconstrained arrays, such as String parameters, are fat pointers to data and bounds.
  • GNAT lists internal variables, such as S23b, beside the program's.
  • Unbounded_String is a controlled record pointing at a shared buffer.

Testing

The point is to find bugs, so each test must let the program, not the test's author, say what is true. No language gets every fixture in every build; each gets the few that cover the most:

  • A values gallery (values.ext) that prints a TRUTH line for each value before it calls reached, the same format as the C, Go, and Rust galleries. The program computes what uscope must show, so a wrong element count, bound, or text fails without anyone having predicted it. Built unoptimized and optimized.
  • A views fixture (containers.ext) with VIEW: markers, the same as the other languages' containers, so every view in the language's file must bind, page, and evaluate back.
  • One stepping scenario on the gallery: break on a function by the name the language writes, step into and out of it, and check the backtrace's names and lines.

The compiler matrix stays compact: one compiler per language, unoptimized and optimized, except Nim, which is built with both GCC and Clang because its output is their output.

Hermetic builds

The compilers join the dev shell from the pinned nixpkgs. gfortran's and GNAT's wrappers ship their own gcc, ld, and binutils, which must not shadow the shell's, and LDC's package adds its runtime's headers and libraries to every C compile and link, which changed every C fixture's recorded switches; so they enter it as wrapper scripts exposing only their drivers, as musl-gcc does. GNAT's gnatmake runs with GNAT's own toolchain first on its path. A compiler that needs anything from the host, or that writes outside build/, is not supported. Every new toolchain joins suite_signature, so a toolchain update rebuilds the fixtures.

Commits

  1. This plan.
  2. One commit per language, in the order Odin, Fortran, D, Nim, Ada: the toolchain, recognition, value support, views, fixtures, tests, and docs.
  3. Each general bug the new fixtures expose: its own commit after the language that found it, with the failing test first.

Dropping a language is then reverting its commit and the fixes whose tests rely on its fixtures, or moving those tests.

Tracker

Each language's cost is its commit, less the docs; the general fixes it needed are counted where they landed.

L1

Odin

done

Odin units by their producer; package-qualified and argument-bearing names; slices, strings, dynamic arrays, cstring, and unions natively; views for maps, queues, small arrays, and builders; a gallery, a views fixture, and a stepping scenario. About 290 lines of source and 340 of fixtures and tests.

L2

Fortran

done

Fortran units; arrays from their lower bounds; character(len=N) as text; gfortran's own variables left out. Descriptor arrays, deferred-length strings, and arrays of more than one dimension, which Fortran lays out column by column, are explicitly unsupported rather than read wrongly. A gallery, naming elements by their source indices, and a stepping scenario. About 100 lines of source, and 160 of a synthetic test for nameless variables.

L3

D

done

D units; slices and strings natively, length first, with wstring and dstring read by their characters' width; D's __ temporaries left out; template names (Appender!string) and types scoped by their dotted modules; views for Appender and Nullable. A gallery, a views fixture, and a stepping scenario. About 210 lines of source and 310 of fixtures and tests.

L4

Nim

done

Nim units by their file names; procedures named as Nim mangles them (values::reached); Nim's own variables left out; its C treated as C for typedefs, bounds, and returns; a view for strings. Seqs keep their elements in a C flexible array member, which uscope does not read, so they wait on that. A gallery built through GCC unoptimized and Clang optimized, and a stepping scenario. About 60 lines of source and 150 of fixtures and tests.

L5

Ada

done

Ada units; subrange types, as GNAT describes Integer_8; GNAT's typedefs seen through; GNAT's own variables left out; arrays with their own bounds, two-dimensional ones by their indices; a view for Unbounded_String. Unconstrained arrays, whose bounds are found at run time, wait on runtime-bounded arrays. A gallery and a stepping scenario. About 60 lines of source and 230 of fixtures and tests.

L6

Closing the gaps

done

One commit per gap the five languages left, each with its test first. Source lines count a file's own unit tests; tests count fixtures and scenarios.

  • Column-major arrays: an ordering on arrays, so that grid(1,2) is Fortran's element. About 160 lines of source.
  • Arrays bounded at run time: bounds, strides, data locations, and allocation states evaluated at inspection, serving Fortran's assumed-shape, allocatable, and pointer arrays and deferred-length strings, GNAT's unconstrained arrays and fat pointers, C's variable-length arrays, and C's flexible array members, which are listed with an unknown length rather than guessed. <not allocated> and <not associated> are values of their own. The largest change: about 1,700 lines of source, including the image's table of run-time dimensions and its validation, and 110 of fixtures.
  • Nim's seqs, now that a flexible array member is indexable: a seq laid out as Nim lays one out is its element type's seq, and a view shows its elements. About 100 lines each of source and tests.
  • break main in Fortran stops in MAIN__: a function records DW_AT_main_subprogram, and main names the main subprogram wherever a program has one. About 70 lines.
  • VS Code: Fortran's fixed form is FortranFixedForm, as the Modern Fortran extension registers it; nothing registers the fortran the manifest named. Odin's, D's, Nim's, and Ada's extensions use the identifiers already listed.
  • Syntax highlighting of the five languages in the CLI and the web page: each language's comments, strings, and keywords, case-insensitive for Fortran and Ada. About 790 lines, two thirds of them keyword lists, and one small stream tokenizer on the page shared by all five. Fortran's fixed form stays plain.
  • Ada's names: values__add is values.add, overload numbers and body marks dropped, and its library unit is its package, so break add finds it. Other GNAT encodings stay raw. About 85 lines.
  • D's symbols: druntime's and Phobos's frames read as what they name, rt.dmain2._d_run_main2.runAll, with template arguments written !(…). A name-only reader of D's mangling grammar, back references included, that refuses anything it does not follow exactly; checked against libiberty over the fixture's 3,838 symbols, it names every one libiberty reads the same, and one libiberty cannot read. About 540 lines.
  • Nim's variables: small_1 is small and value_p0 is value. Nim 2 numbers every local and parameter, and its mangling drops any underscore before a digit, so the number is never part of the name. About 30 lines.
  • Return values of Odin, Fortran, D, and Ada: their scalars, which LLVM and GCC return as C's, pinned by an integer, a double, and a truth value in each gallery at both optimization levels; their aggregates stay unknown. Returned values are named as C's are, without scopes. About 40 lines of source and 190 of fixtures.
  • D's associative arrays: LDC's record of a table pointer with typedefs of its key and value types is AssociativeArray(K, V), and a view reads druntime's table as core/internal/newaa.d lays it out, refusing a table whose key and value sizes are not its types'. About 85 lines.

Findings

Bugs in uscope that the new compilers exposed, and what fixed them.

BugFound byStatus
An array without DW_AT_lower_bound was assumed to start at 0 whatever its language, so a Fortran or Ada array of three showed four elements.gfortran, GNATfixed
A Fortran array of more than one dimension was read row by row, so grid(1,2) showed grid(2,1)'s value.gfortranfixed
A nameless artificial variable was listed as malformed instead of being left out.gfortranfixed
A subrange type used as a type, as GNAT's Integer_8, was unsupported, and so was every array of one.GNATfixed
A slice's text was read from its first word whatever its layout, so a D string, length first, read as garbage.LDCfixed
A slice's text was read as bytes whatever its characters' width.LDCfixed
The pinned nightly rustc describes an unsized tail, [u16] in Tail, as one element inside the record's size, which uscope read as a slice.rustcfixed
The utf8 format refused an array of a typedef of bytes, as Odin's u8.Odinfixed
A typedef in a language the evaluator did not know the meaning of typedefs in blocked evaluation of its values, as GNAT's access types and Nim's integers.GNAT, Nimfixed
An array's DW_AT_byte_stride or DW_AT_bit_stride was ignored, so a strided array was read as adjacent elements. A dimension's stride, as a Fortran array section's, is now read, and an array's own is unsupported rather than misread.gfortranfixed
A returned value was named by its function's DWARF name, so Nim's read _ZN6values3addE3int3int.Nimfixed
The VS Code manifest named the Fortran language fortran, which no extension registers, so fixed-form sources took no breakpoints.Modern Fortranfixed
libiberty cannot read a D symbol whose type refers back to a function type, as std.concurrency.FiberScheduler.create.wrap. Not uscope's; uscope reads it.LDCnoted
Odin's rawptr carries DW_AT_address_class 1, so uscope refuses it as a pointer into another address space. Odin's quirk; uscope is right to refuse.Odinnoted

Deferred

What the gaps left, and what was declined.

  • Each language's expression syntax, declined: expressions are one neutral language for every source language, so a(1, 2) in Fortran and A (1) in Ada are written a[1][2] and a[1].
  • Nim's enums, declined: Nim's C describes an enum as a typedef of an integer, and its enumerators' names are only in the code of the $ it generates, so no debug information names them.
  • GNAT's types and package-level variables keep their encoded names; only subprograms are decoded.
  • Aggregates that Odin, Fortran, D, and Ada functions return, whose conventions the languages leave unspecified.
  • D's thunks (_DThn…), which libiberty does not read either, and highlighting of Fortran's fixed form.
