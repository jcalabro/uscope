# Go: plan

Status: proposed, 2026-10-06. Nothing here is built yet. Decisions marked
*(settled)* were made with the maintainer. Scope is kept deliberately
small: Go support is as simple as it can be while staying rigorous, and
anything that is not needed for that waits.

Go should be as good to debug in uscope as C, C++, and Rust: every command
in `docs/cli.md` and every request in `docs/dap.md` works on Go programs and
says what it cannot show, and the things Go programmers expect from Delve
are there too. This record sets out where uscope stands, what Go's runtime
demands, what Delve does, the decisions that follow, the order of the work,
and how it is tested. It closes the TODO item "Go: source stepping,
goroutines, split-stack backtraces, and composite values".

## Where uscope stands

**What works today.** Every Go fixture is built `-buildmode=pie` with
`CGO_ENABLED=0`, using the pinned Go 1.26.5. Within that, these work:

- Breakpoints, including file:line on generic instantiations, conditions,
  and hit counts.
- Backtraces of a goroutine that is running on the stopped thread, down to
  `runtime.goexit`, with inline frames. Go's register rule is applied:
  callers keep only rsp and rip.
- Scalars, records, embedded fields, strings, slices, typed constants,
  swiss-table maps, channels, interfaces (dynamic type through
  `runtime.types`), and package globals.
- Watchpoints on globals and heap objects.
- SIGURG passed silently.
- `next` and `finish` in a goroutine that never leaves its thread.

No test steps in Go. README.md says so directly: "Breakpoints and continue
only".

**What failed in experiments.** These were run on 2026-10-06 against
small programs (`next`/`step`/`finish`/`bt` in batch mode, plus flight
recordings).

- **`next` completes in another goroutine.** A worker with `id == 3` is
  stopped at a line, and seven other goroutines run the same function. One
  `next` stops in the goroutine with `id == 1`, and a later one in
  `id == 4`. A step belongs to an OS thread (`ActiveKind::Step { thread }`)
  and is identified by its CFA. Goroutines change threads, and threads
  change goroutines.
- **`next` across stack growth runs away.**
  - Stepping through a deep recursion is correct until the goroutine's stack
    is copied.
  - After that, the step never matches its activation again. It runs the
    remaining 20,000 calls through plan breakpoints, which took more than
    200 seconds.
- **An unrecovered panic never stops.** The program prints its traceback
  and exits with status 2.
- **A recovered nil dereference stops as SIGSEGV.** The program would have
  recovered from it, so every `net/http` handler panic stops the session.
- **`runtime.Breakpoint()` cannot be resumed.** It is reported as "an
  unclassifiable native stop cannot be resumed safely", and the session
  can go no further.
- **Backtraces end at every stack switch.**
  - `systemstack` ends with "the outermost frame has no caller".
  - `mcall` gives a garbage frame `runtime.newproc <autogenerated>:1`.
  - `morestack` gives `<unknown>`.
  - `rt0_go` gives a frame at `0x2`.
  - `runtime.clone` runs into its stack's contents.
  - A breakpoint in C called from Go loses every Go frame above
    `asmcgocall`.
  - A Go callback from C skips the C frames between `cgocallback` and
    `asmcgocall`.
- **Parked goroutines are invisible.** Attached to an HTTP server, uscope
  showed 6 OS threads. Four were in `futex` or `epoll_wait` under
  `runtime.schedule`. One of the program's roughly 14 goroutines was
  visible.
- **`step` enters the runtime.** `m["a"] = 1` lands in
  `runtime.mapassign_faststr`, and `append` in `runtime.growslice`.
- **Range-over-func bodies are separate functions.** A body shows as
  `main.main-range1`, and the loop's enclosing variables are not in scope.
  `next` from a `break` in the body goes into the iterator.
- **Values.**
  - `complex64`, `complex128`, and every `func` value are "unsupported".
  - In optimized builds most strings, slices, and interfaces are
    "composite DWARF locations" (also unsupported).
  - Generic values show types `.param0` and `.param1`, and leftover
    floats print hundreds of digits.
  - An escaped variable shows as a pointer named `&x`.
  - Variables not yet declared show garbage (`p = 0x425eb4`).
  - The closure context and range-over-func bookkeeping are listed:
    `.closureptr`, `#yield1`, `.dict`.
  - `time.Duration` prints `1500000000`, and `time.Time` prints
    `{<3 fields>}`.
- **Names.**
  - `break main.Sum` finds no generic instantiation.
  - `break runtime.newstack` resolves to two locations, the ABI wrapper
    first.
  - `n.W` does not find a promoted field.
  - `m["k"]`, `s[0:1]`, `cap(s)`, `uint8(x)`, and `nil` are refused.

The codebase audit agrees, from the code. Nothing outside the DWARF provider
and the presentation of interfaces knows about goroutines, `g`, the
`.gopclntab` function table, or the runtime. `FunctionInfo` records no
language. Simulator scope excludes Go and signal handlers.

## What Go demands

- **M:N scheduling.** Goroutines (G) run on OS threads (M) through
  processors (P). A goroutine changes threads whenever it blocks, is
  preempted, or makes a syscall. A thread runs many goroutines, and runs
  the scheduler on its own g0 stack in between. Most goroutines are parked
  at any stop, so no thread holds their registers.
- **Stacks move.** A goroutine's stack starts small. `morestack` →
  `newstack` → `copystack` replaces it with one twice the size elsewhere,
  and adjusts every pointer into it. GC also shrinks stacks. Any absolute
  stack address kept across a resume can go stale. That includes a CFA,
  a watched local, and a saved activation.
- **Three kinds of stack per thread.**
  - The goroutine's own stack.
  - g0, for the scheduler and for `systemstack` work.
  - gsignal, the signal handler's alternate stack.
  - cgo calls run C on g0, and callbacks from C run Go on the goroutine
    stack.
  - Go's call-frame information (`.debug_frame`) is generated from the
    `pcsp` table alone, the per-function table of stack-pointer offsets:
    CFA is rsp plus a delta. It cannot express any of these switches. It
    describes no rbp rule and no top frame.
- **The runtime's own traceback is the ground truth** (`runtime/traceback.go`).
  It ends at functions flagged `TOPFRAME` (`goexit`, `mstart`, `rt0_go`).
  It stops at `SPWRITE` functions. It jumps from g0 to `m.curg` at
  `systemstack` and `morestack` using `curg.sched`. It treats the caller of
  `sigpanic`, `asyncPreempt`, and `debugCallV2` as an exact faulting PC,
  not a return address. These flags live only in `.gopclntab`.
- **The register ABI preserves nothing across calls.** It keeps the current
  goroutine in r14, but only inside Go ABIInternal code. TLS, at
  `fs_base - 8` for executables, is authoritative everywhere else. That
  covers C code, ABI0 wrappers, and the moment of switching stacks.
- **Faults become panics.** A nil dereference raises SIGSEGV. The runtime's
  handler makes it `sigpanic` → `gopanic`, which may be recovered. An
  unrecovered panic reaches `runtime.fatalpanic` and exits with status 2,
  or raises SIGABRT under `GOTRACEBACK=crash`. Runtime failures reach
  `runtime.throw` or `runtime.fatal`. Examples are a deadlock, a
  concurrent map write, and running out of memory. SIGTRAP is fatal to a Go
  program, so a debugger trap must never reach it.
- **Async preemption.** sysmon sends SIGURG to a thread whose goroutine ran
  10 ms or longer. Wall-clock time spent stopped in a debugger counts. The
  handler redirects the goroutine into `asyncPreempt`, which may park it
  and resume it later on another thread.
- **Threads come and go.** `GOMAXPROCS` plus every M blocked in a syscall.
  Clones happen at any time, including during run control. A goroutine
  that exits while locked to its thread takes the thread with it.
- **The runtime has DWARF too.** Every runtime function is a step target.
  ABI wrappers share their real function's DWARF name. Wrappers are marked
  `<autogenerated>` with `DW_AT_trampoline`. Go statements and defers get
  `gowrapN` and `deferwrapN` closures.
- **Go is versioned and moves.** Upstream supports 1.26 and 1.27; 1.27 was
  released 2026-08-19. Every release changes something:
  - fields of `runtime.g`;
  - the order of wait reasons;
  - goroutine statuses (1.26 added `_Gleaked` and `_Gdeadextra`);
  - `abi.Type` (`TFlagDirectIface` in 1.26);
  - `moduledata` (`typelinks` gone in 1.27);
  - the `pclntab` header (`textStart` always 0 from 1.26);
  - funcID numbering (1.22 and 1.25).
  
  DWARF describes the layouts. It does not describe the conventions.

## What Delve does, and where to do better

Delve reads every runtime structure through the runtime's own DWARF, by
field name with name fallbacks. A CI script fails when a release changes a
field Delve depends on (`_scripts/rtype.go`). It finds the current
goroutine through TLS, and maps g0 and gsignal to `m.curg`. A parked
goroutine unwinds from `g.sched` (pc, sp, bp).

**Stepping.** `next` and `step` are entirely breakpoint-based, with all
threads running. Every internal breakpoint carries the condition
`runtime.curg.goid == G && runtime.frameoff == X`. `frameoff` is
`CFA - g.stack.hi`, so a frame keeps its identity when the stack moves, and
recursion is safe. `step` goes past wrappers and private runtime functions,
and into the goroutine a `go` statement creates (a breakpoint in
`newproc.func1`). It also goes into deferred functions on panic or return.
Range-over-func bodies are stitched to their parent frame (`rangeFrames`).

**Panics and throws.** Internal breakpoints on `runtime.fatalpanic`, and
on `throw`, `fatal`, and `fatalsignal`, report unrecovered panics and fatal
errors. Every other signal is passed straight through.

**Delve's known weaknesses** are uscope's openings:

- **DAP threads.** DAP shows at most 1024 goroutines, filtering after
  truncating. It reports one goroutine per stop even when several stopped.
  It has no stack paging. It reports an interrupted `next` as a fake
  exception, and a new step then fails with "next while nexting".
- **Missing DAP requests.** No `stepInTargets`, `breakpointLocations`,
  `loadedSources`, or `completions`.
- **Optimized and runtime state.**
  - A `DW_OP_piece` with nothing on the stack reads as zero, not as
    optimized out.
  - Memory reads show breakpoint bytes.
  - It knows no goroutine status after 8, and does not mask `_Gscan`.
  - It hardcodes wait-reason tables per version, instead of reading
    `runtime.waitReasonStrings`.
  - It ignores open-coded defers.
  - Its `asmcgocall` offset constant is stale for 1.26/1.27.
- **Conditions.** Breakpoint conditions cost about 2 ms a hit, because
  Delve's ptrace thread is a locked goroutine.
- **Paths.** Paths that do not match fail silently (`-trimpath`, containers,
  Bazel), with no reason given.

## Decisions

**Goroutines are tasks, a neutral concept.** The public model gains a
*task*: a unit of execution a language runtime schedules on OS threads.
Each task has:

- a stable id;
- a state and a wait reason;
- the thread it runs on, if any;
- locations: current, first user frame, creation site, and start function;
- labels;
- a parent task.

Tasks are listed from immutable snapshots per stop, and paged. Threads
stay what they are; a task links to its thread, not the other way round.
Go's goroutines are the only provider this plan builds. The concept is
neutral so that tokio tasks (TODO "First-class tokio support") could
arrive through the same interface later; nothing here is built for them.
Clients address inspection by thread or by task. A `StopContext` names a task when there is one.

**A runtime-model layer sits beside the debug-info providers.**
`src/runtime_model` is pure in the way `src/eval` is. It reaches the
program only through traits for memory, types, and symbols, and a boundary
test keeps ptrace and I/O out. The Go model is in
`src/runtime_model/go/`. For one stop, from DWARF layouts and memory, it
answers:

- the Go version;
- the current g of a thread;
- the task list;
- a parked task's registers;
- how to cross a stack switch;
- which functions are wrappers or private runtime functions;
- where panics and throws report;
- how to read a panic's value.

It is unit-tested against fake memory built from real layouts, and its
results are checked on live fixtures. ELF and `pclntab` parsing stay at
the edge in `src/debug_info`.

**Layouts come from DWARF. Only conventions are written down.**

- Field offsets, sizes, and constants come from the runtime's own debug
  information, by name:
  - the types `runtime.g`, `m`, `gobuf`, `_panic`, `_defer`, `moduledata`,
    and `abi.Type`;
  - the `_G*` statuses and `waitReason*` constants, which Go emits as
    `DW_TAG_constant`;
  - `waitReasonStrings`.
- These are written down, each with the versions that use it:
  - the TLS rule;
  - the names of the functions that switch stacks;
  - the `pclntab` format, keyed by its magic number and the version;
  - the meaning of `_Gscan`;
  - `DW_AT_go_runtime_type` as an offset from `moduledata.types`;
  - `TFlag` against `Kind_`.
- A **runtime contract** lists every name uscope reads.
  - A test checks the contract against every pinned toolchain, as Delve's
    rtype check does.
  - A missing name makes the feature that needs it unavailable, with a
    reason that names the field.
  - A missing name never produces a guessed offset.

**Support the pinned toolchain only** *(settled)*, as uscope does for
every other language.

- `flake.nix` pins one Go, and every Go fixture builds with it.
- Moving the pin is a deliberate change of its own: update the contract,
  the views, and every fixture expectation together. 1.26.5 is now three
  patches behind, and 1.27 is out, so the first move is due.
- The version comes from the compile unit's producer, with
  `runtime.buildVersion` as a check.
- A binary from another release still gets everything static DWARF gives:
  breakpoints, frames, and values of non-runtime types.
- Runtime features in such a binary run only where the runtime contract
  binds against its DWARF. They are reported as unverified for that
  release. They are refused, with a reason, wherever a convention is known
  to differ (`TFlag` against `Kind_`, the `pclntab` header, swiss tables
  against `hmap`). Runtime features are tasks, stack switches, panic
  reports, and interface dynamic types.

**The current goroutine comes from TLS.**

- g is the word at `fs_base + tpoff`.
  - Executables use `tpoff = runtime.tlsg - roundup(PT_TLS memsz, align)`,
    or −8 without `runtime.tlsg`.
  - c-shared libraries use the `R_X86_64_TPOFF64` GOT slot, read from the
    inferior.
- If g is the thread's `m.g0` or `m.gsignal`, the thread is running
  runtime code for `m.curg`.
  - The thread presents as that task, with its frames on the system stack
    marked.
  - When `curg` is nil the thread is idle in the scheduler, or a C thread,
    and has no task.
- Inside `runtime.clone` the TLS slot is not yet valid, and the thread's
  task is unknown.
- r14 is never trusted.
- A g that is not in `allgs` is reported as such, never followed.

**Unwinding crosses stacks the way the runtime does.** The Go caller
provider covers code in Go compile units and the runtime's assembly:

- The CFA comes from `pcsp` (CFI where present, `pclntab` otherwise).
  rbp is recovered from CFA − 16 once the frame is pushed.
- `TOPFRAME` functions end the stack, `Complete`.
- `systemstack`, `morestack`, `mcall`, and `asmcgocall` continue at
  `m.curg.sched` (pc, sp, bp).
  - `systemstack` and `asmcgocall` save `curg.sched` through
    `gosave_systemstack_switch`, so no stack offset is hardcoded.
- `cgocallback` shows the C frames on g0, through `m.g0.sched.sp`, and then
  the Go frames before the call.
- `sigtramp` frames recover the interrupted registers from the kernel's
  signal frame, using `runtime.sigreturn__sigaction` as `sa_restorer`.
  - This is the generic Linux signal-frame unwinder the TODO already asks
    for, so C gains it too.
- The caller of `sigpanic`, `asyncPreempt`, or `debugCallV2` is a trap
  frame: its PC is exact, not a return address.
- Any other `SPWRITE` function ends the stack with a typed termination,
  never a guess.
- `StackFrame` gains a stack segment: goroutine, system (g0), signal, or
  foreign. Backtraces show where the stack switched.
- **Every frame is shown, and runtime frames are marked** *(settled)*.
  Nothing is hidden: the user's code, the runtime, wrappers, and
  system-stack segments all appear. The CLI marks runtime frames, and DAP
  gives them the `subtle` presentation hint.
- The frame-pointer chain is a test oracle, never a fallback.

**`pclntab` is always read.** It survives stripping (`-ldflags=-s -w`). It
gives:

- function names, files, lines, and inline trees for binaries without
  DWARF;
- exact SP deltas for unwinding them;
- function flags (`TOPFRAME`, `SPWRITE`, `ASM`);
- unsafe points.

A stripped Go binary therefore gets named, unwound frames and function and
line breakpoints. Tasks and values need DWARF, and are reported unavailable
without it rather than reconstructed from a version's guessed layout. The
per-step unwind cost is fixed at the same time: `.debug_frame` lookup scans
every FDE linearly today, and an index (or `pclntab`'s `findfunctab`)
replaces it.

**A frame's identity survives a moving stack.** An activation is
`(task, offset of the CFA below the task's stack.hi)` when it belongs to a
task with a movable stack, and `(thread, CFA)` otherwise. Every
cross-resume identity uses this form:

- step and finish activations;
- inline-instance identity;
- watched locals;
- the "returned" test (`rsp >= cfa` becomes a comparison of offsets).

The stack bounds are read again at each stop, so a copied stack still
matches. This is the decision the rest of run control rests on.

**Steps follow the goroutine.** A step, `finish`, or instruction step
belongs to a task when one is known.

- A plan breakpoint hit by any thread whose task is the stepping task
  advances the step. A hit by any other task is repaired invisibly, as
  other threads' hits are today.
- The stepping thread is re-derived at each hit, and the completed stop
  names the thread the task is on by then.
- A signal guard, and the single-step parts of a step (returns and inline
  steps), likewise match by task and activation offset, not by pid and
  rsp.
- A step whose task parks mid-line simply waits: the other threads run,
  and the plan's breakpoints catch the task wherever it resumes.
- Another task's breakpoint, watchpoint, or signal still ends the step
  where it happened, as today for threads. This deliberately differs from
  Delve's "next while nexting"; uscope's step is never left pending.

**SIGURG never interrupts a single step.** A preemption signal that arrives
during a single step or a breakpoint repair is held, and delivered with the
next resume.

- The runtime tolerates late and spurious preemption signals (it rechecks
  `preempt` and safe points).
- Without the hold, the step lands in `asyncPreempt`, and the goroutine can
  resume elsewhere.
- Continuing still passes SIGURG at once, so the program's own
  `signal.Notify(SIGURG)` still sees every one (`preempt-go`).
- uscope does not change the program's environment: no
  `GODEBUG=asyncpreemptoff`. Delve does not either, on linux/amd64.

**`step` skips what the user did not write.** For Go, a step does not stop
in:

- private runtime code: `runtime.` with a lowercase first letter,
  `internal/runtime/`, and `runtime/internal/`;
- `<autogenerated>` and trampoline functions;
- ABI wrappers;
- the stack-check path (`morestack` → `newstack`), when it is entered from
  a user function's prologue.

It passes through them to user code they call. Otherwise it continues as
a step out of them.

- A step that starts in the runtime may stop in the runtime.
- `step` on a `go` statement continues as `next`. `step` into the new
  goroutine is a separate step kind, in a later phase.
- `step` at a `return` enters deferred functions. The open-coded calls are
  ordinary calls; the rest go through a breakpoint in `deferreturn`.
- A panic running defers stops `next` and `finish` in the deferred
  function, as in Delve.
- These rules are a per-language "step filter", so a future Rust filter
  (std internals) fits the same seam.

**Range-over-func bodies are logical frames of their parent.**

- A `-rangeN` body presents like an inline frame of its parent function.
  Its frame shows the parent's variables, without `#yield`, `#state`, or
  `.closureptr`.
- `next` in a body treats each call into the iterator as a call. It stops
  at the next body line or the line after the loop.
- The iterator function's own frames stay visible in the backtrace, marked
  as what they are.
- This reuses the logical-frame machinery inline frames already have.

**Panics and fatal errors are stops of their own.** A new neutral stop
reason, a *language exception*, is reported:

- at an unrecovered panic, from a breakpoint on `runtime.fatalpanic`;
- at a fatal error, from `throw`, `fatal`, and `fatalsignal`;
- at every panic, from `gopanic`, only when the user asks.

It carries the message the runtime would print (`preprintpanics` has
already converted errors and Stringers to text), the value as an
inspectable expression, and the chain of nested panics. The frame selected
is the one that panicked, below `gopanic`, or the faulting frame below
`sigpanic`. Rust panics and C++ throws can use the same reason later.

**Faults are handled as Delve handles them, not as gdb does**
*(settled)*. In a Go process, SIGSEGV, SIGBUS, and SIGFPE are passed to
the program without stopping or printing. The runtime's handler decides
what they mean, and uscope stops at its verdict.

- A fault in Go code becomes a panic. If it is recovered, nothing
  happened. If it is not, the unrecovered-panic stop reports it, with the
  faulting frame selected below `sigpanic`.
- A fault the runtime cannot turn into a panic reaches `fatalsignal` or
  `throw`, so the fatal-error stop reports it. That covers a fault in C
  code during a cgo call, or one inside the runtime. The faulting frame is
  reached through the signal frame.
- These are only the default policies for a Go process. `handle SIGSEGV
  stop` still makes the raw signal stop.

**`runtime.Breakpoint()` is a breakpoint.** An `int3` in the program's
own text that uscope did not plant stops as a *program breakpoint*, and
resumes past it. Its SIGTRAP is never delivered, since SIGTRAP is fatal to
a Go program. C's `__builtin_debugtrap` gets the same.

**Go names resolve the way Go programmers write them.** Function locations
accept:

- `pkg.F` by package name (`DW_AT_go_package_name`) or by full import path;
- `F` in the stopped frame's package;
- `(*T).M`, `T.M`, and `pkg.(*T).M`;
- generic base names, which match every instantiation: `main.Sum` finds
  `main.Sum[go.shape.int]` and the rest;
- closures, as `main.main.func1`;
- `file.go:F`.

ABI wrappers, trampolines, and `<autogenerated>` code are never chosen.
Inlined copies of a function get breakpoints too. A line with no statement
is refused with the nearest lines that have one, never moved silently.

**Values come out as Go shows them.** The provider normalizes the
following:

- **Complex numbers** (`DW_ATE_complex_float`); C `_Complex` gains it too.
- **`func` values** show their target function and, for closures, their
  captured variables, through `DW_AT_go_closure_offset`.
- **Escaped variables** (`&x`) present as `x`.
- **Result parameters** (`DW_AT_variable_parameter`, `~r0`) are grouped as
  results. After `finish` they are shown as the returned values, which is
  TODO's "show a function's return value after finish".
- **Visibility.** A local is in scope only after its declaration line, per
  Go's producer rule. Lexical-block ranges that Go emits outside their
  parent are fused, as Delve does.
- **Compiler temporaries** are hidden from `print`: `.dict`, `.closureptr`,
  `#yield*`, `#state*`, and `.autotmp_*`. They stay reachable by name.
- **Shape-typed values** resolve their real types: `.dict[DW_AT_go_dict_index]`
  is an `*abi.Type`, which maps through `DW_AT_go_runtime_type`. A value
  that cannot be resolved keeps its shape type and says why.
- **Composite locations** (`DW_OP_piece`), with partial values marked
  partial. Optimized Go needs them for every string, slice, and interface
  in registers. This is TODO's existing item.
- **Interfaces** find `moduledata.types` through `runtime.firstmoduledata`,
  not an ELF symbol, so stripped symbol tables work. The
  runtime-type-to-DIE lookup is a map, not a scan.
- **Typed constants** only make a type symbolic when the value matches a
  constant, or an OR of flag constants. `time.Duration` stops being an
  enumeration.
- **New built-in views:**
  - `time.Duration`, using the existing duration formatter;
  - `time.Time`, as wall time, location, and monotonic reading;
  - `sync.Mutex`/`RWMutex` state;
  - `atomic.*` values;
  - `strings.Builder` and `bytes.Buffer` as text;
  - `[]byte` as text when it is valid UTF-8;
  - error chains.
  
  Each is verified against every pinned toolchain by `VIEW:` markers.
- **A pointer into a goroutine stack** below the goroutine's current sp is
  reported as stale. Go leaves dead slots holding pre-copy addresses
  (go#75124).

**Watchpoints on Go stack objects move with the stack.**

- A watched local's identity is its task and its offset below stack.hi.
- An internal breakpoint at `runtime.copystack`'s return, matched to the
  task being copied, moves the debug registers.
- Leaving the frame ends the watch, as for C locals.
- Debug registers are already armed on every thread, so the watch follows
  the goroutine across threads.

**uscope never calls functions in the program** *(settled)*. Calling
through `runtime.debugCallV2` is neither implemented nor planned. It
would need the other threads running during the call, which breaks the
all-stop model; the expression language excludes calls for every
language; and uscope calls into no C or Rust program either. Values that
Delve users get from `String()` and `Error()` come from views and from
the message the runtime has already formatted for a panic. If calls are
ever wanted, that is a redesign of its own.

**Expressions gain neutral forms, and `nil`** *(settled)*.

- These forms are added for every language:
  - `cap()`;
  - member lookup through embedded (promoted) fields;
  - map indexing by key, through the map's view;
  - slicing, `s[a:b]`;
  - a name for the current task, such as `$task`, so a condition can
    select a goroutine.
- `nil` becomes a second spelling of `null`, in every language. The design
  record's "one spelling of null" rule and its hint change with it.
- Go's conversion syntax `T(x)` and type assertions `x.(T)` stay out.

## Architecture

- **`src/model.rs`, `src/protocol.rs`.**
  - Add `TaskId`, `TaskSnapshot`, and `TaskQuery`/`TaskPage`, with filters

## Runtime facts the plan depends on

Verified on Go 1.26.5 with gdb 17.1 and GOROOT sources, and diffed against
the 1.21–1.27 release branches.

- **DWARF and sections.**
  - DWARF 5 is the default from 1.25, with `.debug_loclists`/`addr`/
    `rnglists`, zlib `SHF_COMPRESSED`, and one compile unit per package.
  - The producer looks like `Go cmd/compile go1.26.5; regabi`. `-N -l`
    appears when given.
  - `.debug_frame` only. cgo builds add `.eh_frame` for their C objects.
- **Runtime types in DWARF.** `runtime.g` (456 bytes), `m`, `gobuf`, `p`,
  `_panic`, `_defer`, `moduledata`, `abi.Type`, `allgs`, `allglen`, `allm`,
  `waitReasonStrings`, `buildVersion`, and every `_G*` and `waitReason*`
  constant are present in both `-N -l` and optimized builds.
  `atomicstatus` is an atomic wrapper with a `value` member.
- **Line tables.**
  - `prologue_end` follows the frame setup.
  - The `morestack` block at a function's end carries the declaration line,
    and jumps back to the entry, so an entry breakpoint fires twice when
    the stack grows.
  - Frameless leaf functions have no `prologue_end`, and their entry row is
    not a statement.
- **Generics, closures, escapes, and results.**
  - Generic instantiations are separate subprograms named
    `F[go.shape.T]`, with a `.dict` parameter and `.paramN` typedefs
    carrying `DW_AT_go_dict_index`.
  - Captures carry `DW_AT_go_closure_offset` (1.23+). Escaped variables are
    `&x` pointers. Results are `~rN` with `DW_AT_variable_parameter`.
- **Wrappers.**
  - Wrappers have `DW_AT_trampoline` and file `<autogenerated>`.
  - ABI0 wrappers share their function's DWARF name. Their ELF names end
    `.abi0`, and there are 38 duplicates in a small optimized binary.
- **TLS.**
  - A static executable uses `FS:-8`.
  - An internal-link PIE uses a `.tbss` of 8 bytes with no `runtime.tlsg`,
    and its link base is `0x400000`.
  - External linking has `runtime.tlsg` `STT_TLS` after C's TLS.
  - c-shared uses an IE GOT slot.
- **`pclntab`.**
  - Its magic is `0xfffffff1` for 1.20–1.27.
  - It is present in PIE, cgo, and `-s -w` binaries.
  - `debug/gosym` recovered all 1966 functions of a stripped binary from
    it.
- **Panics.**
  - `fatalpanic(msgs *_panic)` takes `msgs` in rax at entry.
    `msgs.arg` is an eface at offset 0, and `link` chains nested panics.
  - `fatalpanic` calls `crash()` outside `systemstack` on purpose, so the
    stack stays clean.
  - `GOTRACEBACK=crash` makes every M raise SIGQUIT before SIGABRT.
- **SIGTRAP and code bytes.**
  - SIGTRAP is `_SigThrow`.
  - Go reads its own code bytes only to print a crash on SIGILL or SIGFPE,
    and when `GODEBUG=fips140=on` checks the FIPS module's text. A
    breakpoint in the FIPS module before its `init` therefore fails that
    check, so such breakpoints wait until `init` has run.
- **Heap layout.** Go reserves gigabytes of `PROT_NONE` heap. A `gcore` of
  a trivial program was 1.26 GB, so core tests use filters that skip it.
  Heap addresses are randomized from 1.26 (`GOEXPERIMENT=norandomizedheapbase64`).

## Testing

Few tests, each with high leverage, as elsewhere.

- **The program is its own oracle.** At each synchronization point, a Go
  fixture prints the runtime's own view of itself and then reaches a
  breakpoint. That view is `runtime.Stack(buf, true)` (every goroutine:
  id, state, wait reason, frames, creation site).
  - The test compares uscope's task list and every task's backtrace
    against it.
  - This needs no external debugger, and covers every release in the
    window by construction.
  - The frame-pointer chain is a second oracle for backtraces.
  - gdb is not an oracle for Go: it unwinds into garbage at every
    stack switch.
- **The steps that failed become deterministic tests.**
  - **Another goroutine runs the stepping goroutine's lines on its
    thread.** Build with `GOMAXPROCS(1)`: the stepping goroutine blocks on
    a channel mid-step, and a sibling runs the same function on the same
    thread. Fails today.
  - **The goroutine resumes on another thread.** A sibling holding
    `LockOSThread` occupies the original M, so the goroutine must resume
    elsewhere; the fixture prints the thread ids it observes.
  - **Stack growth.** A recursion grows its stack at a depth the fixture
    controls. The test covers `next` over that call, `finish` from a frame
    whose stack moves, `step` into a prologue that calls `morestack`, and
    a function breakpoint that hits once, not twice.
  - **Preemption.** A goroutine spins long enough to be preempted during a
    single step.
  
  Each test is written first and seen to fail.
- **Panics and runtime breakpoints.** Unrecovered panic, recovered nil
  dereference (no stop), nested panics, `throw` via a deadlock and via a
  concurrent map write, and `runtime.Breakpoint()` resumed. Plus the same
  crash as a core.
- **Fixtures across the matrix.**
  - The pinned Go; `-N -l` and default; PIE and non-PIE.
  - cgo built by gcc and clang; `-s -w`; `-trimpath`.
  - The existing value fixtures gain complex, func, closure, escape,
    shape, result, and range-over-func markers. Their `VIEW:` markers
    cover the new views.
- **Scenarios** through `tests/support::Scenario`, including DAP traffic
  with goroutines as threads, and `just stress` on every run-control test.
  Async preemption and thread churn are what stress exposes.
- **Unit tests only where the logic is intricate.**
  - The runtime model on fake memory, with the stack-switch table and TLS
    offsets.
  - The `pclntab` reader against `debug/gosym`'s output, recorded when
    the fixtures are built.
  - The fuzz target for `pclntab`.
- **The simulator does not model Go's runtime** *(settled)*. It has no
  goroutines, no moving stacks, and no Go golden programs. Go support is
  tested on the real kernel only, with real Go programs. Generic run-control
  changes that the plan makes are still swept as they are today: task
  identity, stack-relative activations, and holding signals during single
  steps. Changes made for Go must not weaken any existing oracle.

## Known limits

These remain after the plan.

- A parked goroutine has only pc, sp, and bp. Its innermost runtime
  frames' register values are not saved.
- Tasks and values need DWARF. A stripped binary has named frames only.
- Goroutines cannot be frozen or resumed individually. Neither the runtime
  nor any debugger supports that (go#31132).
- Optimized Go loses values to its own DWARF gaps (go#67130, go#72053).
  uscope reports them unavailable, but cannot recover them.
- No functions or methods are called, so a value is never shown through
  its `String()` or `Error()` method unless a view or the runtime provides
  the text.
