uscope plan

Program information at the speed of the machine

uscope turns a program's debug information into one immutable model that every client shares. Today it builds that model as a graph of many small heap objects through repeated serial passes and has no persistent image cache. This plan moves metadata into compact tables, builds them in parallel, and caches their validated bytes. The objective is substantially faster loading and lower memory use while preserving every supported debugger answer.

Summary

Ten times the work it should take, on one core

450 msto load the tokio server fixture (4.3 MiB of .debug_info). gdb takes 70 ms, lldb 110 ms.
42×the cost of decoding every attribute of every DIE once (10.8 ms on one thread, 1.5 ms on eight).
failson uscope's own debug build (162 MiB .debug_info) after 7.4 s and 3.5 GB. gdb loads it in 1.1 s.
6.4 Mheap allocations and 1.04 GB allocated to load a 15 MB executable; 178 MB live at peak.
10×type nodes per distinct spelling: 60,839 nodes for 6,073 names. This is not a count of equivalent types.
80%of the time of the debugger, tokio, and Go test suites is spent loading debug information: 191 s of 237 s.

The fix is a different shape for the data, not a faster version of the same code:

  1. One canonical payload. Tables contain fixed-size records, typed local indexes, string pools, and side arrays. Ownership handles and session bindings live outside the persisted bytes.
  2. The bytes in memory are the bytes on disk. A header, a directory, and aligned tables, written with write_all. Inputs and cached images are read into owned, aligned memory and validated before use.
  3. Ingest in parallel by compile unit and by section on a bounded pool, then merge in unit order so the image is byte-identical for any number of threads.
  4. Build each thing once. One sequential DIE decode per unit followed by explicit resolution passes; conservative type deduplication; pooled strings; persisted indexes.
  5. Never guess. Instrument once and feed every reader: text and JSON reports that people, scripts, and coding agents can diff, Tracy for people at a screen, and deterministic instruction and allocation benchmarks that fail when a change regresses them.
  6. Never do it twice. Images are cached by content, so a program uscope has seen loads in milliseconds: every re-run, every shared library, and every test fixture.

Principles

What the data-oriented talks teach, applied here

Two talks set the method: Mike Acton's Data-Oriented Design and C++ (CppCon 2014) and Andrew Kelley's Practical Data-Oriented Design (Handmade Seattle 2021), which applies it to the Zig compiler. Debuggers that load fast have converged on the same ideas: RAD Debugger's RDI format, GDB's cooked index, LLDB's manual index, LLVM's GSYM, and Sentry's SymCache.

The purpose of all programs, and all parts of those programs, is to transform data from one form to another. … If you don't understand the data you don't understand the problem.Mike Acton, CppCon 2014
Think about a struct that you have the most of in memory and think about how you can make it smaller. That's the whole trick.Andrew Kelley, Handmade Seattle 2021

What the hardware charges

Pointer chasing, allocation and repeated decoding are plausible costs, but fixed cycle counts do not establish their contribution here. Cache topology, dependent versus independent loads, allocator state and parallel bandwidth all matter; aggregate L3 capacity is not necessarily equally accessible to every core. Use the measured profiles below to select work, and counters to assess a proposed layout.

The rules

P1

Know the data, then shape it

Design from measured distributions. Record the frequency of generics, nonzero discriminators, location-list lengths and confirmed duplicate types. Optimize the common shape while preserving a lossless uncommon representation. Each encoding cites its measured distribution.

P2

Where there is one, there are many

No API works on one function, one type, or one DIE at a time when the caller has thousands. Ingestion transforms arrays into arrays; lookups search arrays; shared libraries load as a batch.

P3

Indexes, not pointers

Records refer to each other by u32 index wrapped in a distinct type per table, the Rust form of Zig's enum(u32) handles: half the size of a pointer, no allocation, no reference count, valid on disk. An absent reference is u32::MAX, not an Option that doubles the field.

P4

Encodings, not one enum for everything

A tag byte plus a fixed payload, with variable-length data in side arrays, can avoid paying for an enum's largest variant on every row. Count the side arrays too, and measure the cost of fetching them. Flags can fold into tags when decoding remains explicit.

P5

Bools and rare fields out of band

A field set on 1% of rows lives in a sparse side table keyed by row, or the rows are sorted so the flag is implied by which range a row is in. A bool in a hot record can push a hot field onto a second cache line.

P6

Split by access, not by concept

Columns that searches scan (names, start addresses) are arrays of their own; fields read together stay together in measured compact records. Keep keys contiguous and fetch the value once found; no arbitrary record-size ceiling overrides semantics.

P7

Do it once, ideally offline

Each string is interned once, each type built once, each index sorted once, and the result kept on disk so it is never computed again for the same file. "The best code is code that doesn't need to exist. Do it offline. Do it once."

P8

Every core, by default

Ingestion is written to run on all cores from the start, as RAD Debugger's converter does ("multi-core by default"), with per-worker accumulators merged afterwards as LLDB does, and no global lock on the hot path.

P9

Measure the cost before and after

"If you don't understand the cost of solving the problem, you don't understand the problem." Every change states its expected effect in instructions, allocations, bytes, or misses, and the benchmark shows whether it happened.

Why

Root causes

F1

Seven walks on one thread

Every DIE of every unit is decoded in at least seven full passes: function metadata, evaluation units, the type arena's setup, two for globals, the main variable walk, and named constants, plus extra walks for Go units and random reparses through origin chains and type references. Nothing runs concurrently.

gimli's entry reader: 1.9 G of 6.3 G instructions; each full walk ≈ 169 M instructions.
F2

Every unit's copy of every type is built

rustc describes a type again in every codegen unit that uses it. The type builder gives each copy its own TypeId, builds its members and variants, renders its name, and formats an identity key. Identity strings are later parsed back (TypeName::parse, 6.8% of instructions), and the key index is built twice.

60,839 type nodes, 6,073 distinct names (10×); o3 build: 31,781 for 4,405 (7×).
F3

Strings are copied, not interned

Every name read becomes a new String and then an Arc<str>; every source location joins a new PathBuf from the comp dir, directory, and file name; from_utf8_lossy is 4.9% of instructions on its own.

538 K string and 313 K path allocations for 813 distinct files.
F4

Records are constellations

Each record owns several heap allocations through Arc<str>, Arc<[T]>, Option<Arc<…>>, Box, and maps. Reading one function or type touches several unrelated cache lines, and building the model is dominated by the allocator: __rust_alloc alone is 5.7% of instructions.

6.4 M allocations per load. TypeIdentity ≥ 5 allocations; Expression ≥ 3.
F5

Wide, padded records

Fields are sized for the worst case: u64 lines and columns, usize keys, Option wrappers that double a field, rarely set fields stored on every row. The two line tables cost 136 B per row where 12 B would do.

See the record table above.
F6

A quadratic pass for Go

visibility::after_declaration collects and sorts every line boundary of a local's function, once per local, and stores the resulting visible ranges on the local. Large Go functions have thousands of boundaries and dozens of locals.

server-go-o0: 34,245 locals, 39.2 M addresses sorted, 83% of 14.7 G instructions; the reason Go loads take ~0.9 s and up to 571 MB.
F7

Caps from building everything eagerly

Because every object is materialized as heap records, the loader guards itself with image-wide caps. MAX_DATA_OBJECTS is a hard failure, so large programs cannot be debugged at all.

uscope's own debug build fails at 262,144 data objects after 7.4 s and 3.5 GB.
F8

Linear and repeated lookups

die_reference scans every unit for each DW_FORM_ref_addr; function_index_at scans backwards without a bound; populate_record_member_declarations re-collects a record's members once per member; the separate-debug-file fallback can run the whole load twice.

Found by the survey of src/debug_info; each is small today and large on big programs.
F9

Nothing survives the process

Each session loads everything from scratch: the same fixture in every test process, libc on every launch, shared libraries one after another on the controller thread.

191 s of 237 s in three test suites; libc loaded 668 times.
F10

Owned copies cross the boundary

Replies and evaluation clone model records: StackFrame.function: Option<FunctionInfo>, Variable.type_info: Option<TypeInfo>, TypeSource::type_info() returning an owned TypeInfo. Every clone bumps several reference counts on shared cache lines.

model.rs:3582, protocol.rs:77–617, eval/types.rs:68.
F11

No way to see any of this

The flight recorder records requests and ptrace traffic, not where time goes. Each investigation so far has meant temporary eprintln! timers, Callgrind, and DHAT with a patched allocator.

This page needed three throwaway instrumentation patches and two prototypes.
F12

Unoptimized development builds

The dev profile ran the loader at opt-level 0, 7.5× slower. Fixed in d089093: just run builds with the test profile (3.8 s → 0.9 s).

Kept here so the baseline is honest about what is already done.
Design

The image: one buffer of typed tables

A loaded module's static metadata becomes an image: one 64-byte aligned byte buffer holding a header, a directory, and a fixed set of tables. Each table is a slice of one #[repr(C)] record type, reached through a typed view; nothing in the buffer is a pointer. The public ModuleImage stays the immutable, shared model the architecture describes; it becomes a cheap handle (Arc of the buffer plus the parsed directory) whose accessors return small borrowed views instead of references to heap records.

The canonical payload is a pure function of selected input bytes, target description and normalization version. ModuleImageId, executable/display paths, filesystem stat tuples, debug-search provenance, source maps, external view settings and load bias live in an outer binding. Internal type edges contain only local TypeIds; accessors add the binding's image ID. Embedded .debug_uscope_views content is input metadata and must remain represented, with any compiled view runtime separately accounted. Cached payloads can be rebound without patching their bytes.

Lossless compact fields

The 20-byte line illustration is the common case, not a restriction on valid metadata. LineNumber and ColumnNumber currently hold u64; reserve compact escape values and store wide values in keyed side tables. Preserve missing locations separately from line zero, unknown columns, wide language codes (Other(u16)), discriminator/ISA/op-index, declaration columns, and every flag. No cast may truncate to fit a target size.

Keep all row boundaries needed to derive ranges, including compiler-generated gaps and sequence ends that are not public statement rows. Same-address runs retain ordinal order and the current last-statement precedence. A compact range-to-selected-row index is acceptable; eliminating duplicate location records does not require recomputing selection on each query.

For Go locals, first test lexical scope membership, then find the directly inlined call in that scope's code instance; use its call-site location, otherwise the line at the PC. Hide a local only when that location is in the declaration's file and its line is ≤ the declaration line. Missing locations and other files stay visible. Apply this predicate in name binding, enumeration, inspection and any API exposing visibility ranges; measure repeated-query costs as well as load time.

Design

The boundary: views and ids, not owned records

ModuleImage is public API: tests, the CLI, DAP, the web server, the evaluator, views, the runtime models, and the Linux backend call about sixty accessors on it, and integration tests match on TypeKind 28 times. The redesign keeps the accessor names where they still make sense and changes what they return:

  • Views. image.function(id) returns Function<'_>, a Copy pair of image and id whose methods (name(), declaration(), instances()) read the tables. Iterators yield views. &str borrows from the pool.
  • Types as a decoded key. Expose a neutral borrowed type descriptor through object-safe TypeSource methods, backed by image views or by the evaluator's fake target. Member/argument iterators must not require constructing owned slices. Keep src/eval independent of src/image, DWARF and I/O; preserve its boundary test. Resolve the trait/lifetime design in P3.1 before changing all consumers.
  • Ownership across the protocol. Borrowed views never cross an asynchronous channel alone. In-process results may carry IDs with an Arc image owner or an immutable snapshot that pins the owner; an ID-only reply is insufficient for an unloaded module or old session. Keep browser/DAP wire DTOs rendered and self-contained. Any wire change needs a separate request/response design, ts-rs regeneration and transcript tests.
  • One model, not two. DwarfVariableInfo's catalog, call sites, and location expressions move into the image's tables. What remains of the provider is evaluation code over tables, so the VariableInfo trait's eighteen methods operate on ids into one buffer.

Port one family and its consumers together, using temporary adapters where dependencies require them. This is not entirely mechanical: ownership, type equality and partial metadata need explicit compatibility tests. Optimize measured clone costs without forcing a wire-protocol rewrite into the storage migration.

Design

Ingestion: every core, deterministic output

S0

Resolve inputs

bounded I/O

Open descriptors, establish identities, resolve separate-debug policy and probe the selected-input cache key. A hit returns only after validation and session binding; a miss snapshots bytes into owned buffers.

S1

Sections

parallel by section

Decompress compressed sections concurrently; read ELF symbols, dynamic symbols, PLT and GOT; index .eh_frame and .debug_frame FDEs; read .gopclntab; parse unit headers and abbreviations.

S2

Decode

parallel by unit, largest first

One DIE decode per unit into compact raw records, including attributes needed by later analyses. Decode line programs separately. Retain local and cross-unit fixups; do not recursively reconstruct types while walking DIEs.

S3

Resolve and merge

ordered IDs, parallel work

Assign raw global IDs, resolve references and origin/specification chains, normalize scopes and identities, then conservatively deduplicate with a remap table. Forward and cyclic references remain representable.

S4

Analyses

dependency ordered

Finalize type names and indexes; refine prologues and Go frames. Normalize coroutine layouts before decoding resume points and held ranges. Preserve dependencies already present in load_image.

S5

Indexes and seal

parallel by index

Build deterministic indexes, place tables at final offsets and validate. Publish the immutable payload, and write it to the cache once P5 exists.

Per-unit batches

S2 fuses repeated DIE decoding, not all dependent analyses. Worker-local scratch is reused; completed batches have independent ownership. A fixup key is (input, section, unit, DIE offset, reference kind), not an unqualified offset: DWARF 4 .debug_types, DWARF 5 type units, local references and type signatures have different namespaces. Resolve global references with a unit interval lookup plus an exact DIE-start lookup; offsets into headers or attributes are errors. Preserve missing/duplicate signatures, origin precedence and cycles, and explicitly unsupported supplementary/split DWARF states. No new producer support is implied by the rewrite.

Big units

The largest unit holds 19% of the tokio server's DIEs, but DIE count is not measured per-unit work. The reported 10.8/1.5 ms speedup already exceeds the simple equal-cost 5.3× bound; P0 must reconcile setup cost and work distribution. Split large units only after a trace establishes a bottleneck. Any split must preserve ancestor scope, namespaces, unit context, forward fixups and deterministic order; validate producer sibling offsets rather than trusting them as job boundaries.

Types

First build a complete raw graph with stable IDs and resolve all edges. Preserve incomplete, malformed and opaque nodes. Compute strongly connected components with an iterative algorithm; process their dependency DAG bottom-up, but allow forward/back edges within a component. Final IDs follow first representative order, not an impossible requirement that every edge decrease.

Start with conservative deduplication of acyclic nodes. A candidate key covers the complete observable payload and declaration identity: language, qualified/anonymous/local scope, generic values and arguments, qualifiers, sizes, signedness, member/base order and layouts, array bounds, enum origin, variants, address classes, Go runtime attributes and metadata failures. Names and layouts alone never authorize merging nominal types. Where the producer does not establish compatible provenance, retain separate nodes; retaining duplicates is acceptable.

For cyclic candidates, either retain them initially or compare whole SCCs using a bounded, memoized, edge-labelled bijection between nodes, including external canonical edges and the same identity eligibility checks. Hashes only choose candidates; compare all relevant fields and edges before committing a remap. Bound comparisons in collision buckets and retain duplicates when the deduplication work budget is exhausted. Use a forced constant fingerprint test to verify this behavior.

Keep storage identity and same_type distinct. An interned TypeIdentityId replaces repeated identity strings, but local TypeId equality proves only that two references name the same stored node. Preserve TypeIndex's aliases, template matching and ambiguity semantics through the neutral lookup API; any correction to current semantic equality gets its own failing behavioral test and change. Record actual merge counts by reason before assigning a size or node-count budget.

The pool

Use one shared dedicated Rayon pool per process, bounded by CPU availability and memory admission, defaulting to at most 16 workers. Configuration precedence is an explicit loader option, USCOPE_JOBS, [debug_info] jobs, then default; reject zero/invalid counts and expose the effective count. Nested section/unit/index work uses this pool, not a pool per module. Bounded job/completion queues and cooperative cancellation prevent unbounded outstanding loads. Network discovery uses separate bounded I/O capacity so it cannot occupy CPU workers. Never block a pool worker waiting on work that only that pool can run; test jobs=1. Rate-limit progress messages and keep counters worker-local. The simulator prepares images outside the world and uses its deterministic loading edge inside it.

Memory

Peak memory includes owned inputs, decompressed sections, raw batches, fixups, deduplication scratch, sort scratch, final output, and allocator retention. A ≤2× final-image bound is not justified. P0 measures each component; P1 implements byte admission before decompressing or scheduling a batch and checked output reservations. Cap decompressed sizes and total work, keep recursion limits, and return a typed resource-limit error with phase and requested bytes. Reduce concurrency when memory is tight. Incremental merging alone does not free unresolved graph data; external spilling is deferred unless measurements require a separately specified algorithm. Report heap and RSS separately.

Design

Persistence: the bytes are the format

The sealed payload is written directly with write_all (a syscall may write only part). Loading reads it into an owned aligned buffer and validates the entire payload. Validation and the checksum touch every byte anyway, so mapping the file would save only the copy, about a millisecond for the tokio server's image; see I7.

The cache

  • Where. Use $XDG_CACHE_HOME/uscope/images/ (or the standard home fallback), overridden by USCOPE_CACHE_DIR. Create the directory with mode 0700. Write a uniquely created temporary file in that directory, complete and close it, then atomically publish it. Never truncate a published inode. Concurrent writers of the same key are harmless; missing files after eviction are misses. Enforce a default 4 GiB cap when the cache is opened, evicting the oldest entries by modification time. Unwritable/read-only/full caches degrade to uncached loading with a notice.
  • Keys and discovery. Resolve the selected debug-file inputs under current search options before choosing a payload. Hash executable and selected debug-file contents even when build IDs exist; build-id and debuglink still verify pairing using existing rules. Include format and normalization revisions. A persistent stat index is a lookup hint, not proof of equal content; start with content verification on every cross-process hit. Same-process reuse may retain the already owned Program snapshot. Any faster identity path needs a separately stated filesystem trust contract and measured benefit. Recheck negative/unusable debug-file discovery on a later load so a newly installed file or enabled debuginfod takes effect.
  • Trust. Validate format and semantics before exposing views. Corruption becomes a reported miss; remove only the exact bad entry observed, not a concurrently replaced good file. A checksum detects accidental damage, not malicious substitution of valid-looking metadata. This is a private local optimization, not an authenticated shared-cache protocol. --no-cache disables reads and writes; library options and isolated test roots provide the same control.
  • Writing. A cold load writes its entry synchronously after sealing, which costs milliseconds for the fixtures' images, and a failed write is reported and otherwise ignored. A background writer would add a queue, a memory charge and shutdown cancellation; add it only if P5's timings show the write on the load's critical path.

Validation before publication

Validate the fixed header and actual file length first, with checked arithmetic; then checksum, directory and table contents. Enforce unique required table kinds, exact stride/count/length agreement, alignment, non-overlap with header/directory/trailer, maximum byte and work budgets, valid flags/tags and zero padding. Check every span, string reference, local ID, address range, and parallel-column length. Check sorted indexes and their coverage/correspondence to records, not just whether IDs are in bounds. Validate parent graphs as forests where required; type graphs may cycle. Use iterative bounded algorithms and avoid rescanning a long string for every suffix or a huge collision bucket quadratically. Decode opaque DWARF/CFI through gimli with the existing evaluation limits; structural image validation does not make expression execution trusted.

Cache invalidation covers changes to normalization, demangling, type equality, Go/pclntab handling, generated indexes and embedded view semantics even if all field layouts stay identical. Bump the normalization revision deliberately, with a compatibility test and review checklist. A layout fingerprint cannot infer these changes from Rust structs.

Reading files

Every byte uscope parses is an owned copy (D3). There is no new unsafe code here: zerocopy views an owned, 64-byte aligned buffer.

  • Input snapshots. Read from one descriptor into bounded owned storage; compare descriptor metadata before/after reading and retry at most twice before a typed changed-input failure. Parse and hash those owned bytes, never a second path read. Metadata checks detect ordinary rewrites; they do not prove an atomic snapshot against adversarial mutation. Preserve process-executable identity and /proc handling for attach/deleted executables. Do not drop ExecutableSource.data until load bias, link-map, core-dump and simulator consumers have explicit replacements.
  • Edge cases are explicit. Open then fstat the same descriptor; reject unsupported file types and excessive lengths. An empty file fails image validation because a header is required.
  • Cached images are read the same way, then validated. Cache files are published by rename and evicted by unlinking, so a reader never sees a partly written entry.

What it buys

  • Re-running uscope on an unchanged program, which is most of a debugging session's restarts, costs reading and hashing its inputs, then reading and validating the image.
  • libc, ld.so, and every other shared library are ingested once per machine, not once per launch.
  • A separate cache-warm recipe runs after fixtures and the matching loader are built, using target/image-cache. Do not make fixture compilation depend on the debugger executable (that would create a recipe cycle). Core correctness tests keep an explicit cold lane; cache tests use ScratchDir, never the user's cache.
Design

Runtime: managing images during a session

  • Shared libraries load as a batch. Today Controller::refresh_modules loads each newly observed module in turn on the controller thread. It keeps every live-process read, trap reconciliation, link-map/vDSO collection and identity check, then hands the files of all new modules to the pool at once and waits for the batch. Workers receive owned bytes or paths plus policy, never ptrace capability. The controller registers the results in observation order, assigning module IDs and resolving pending breakpoints exactly as it does now, before the stop is published. Preserve today's explicit unavailable-module behavior.
  • Control stays as responsive as today. The controller already blocks while modules load; the batch only shortens that. With P5, libc, ld.so and the vDSO are cache hits. Loading modules asynchronously behind a generation barrier is an idea (I8), not a phase.
  • Lookups preserve overlaps. Keep the existing RangeIndex semantics in flat storage: interval augmentation and explicit tie rules for nested/discontiguous instances, overlapping symbols and line sequences. For example, a predecessor search at 30 in ranges [0,100), [10,20) misses the outer range. Require query cost and scan-length benchmarks on heavy overlap; use existing interval indexing or a bounded interval tree, not an unbounded backward scan.
  • Less copying at a stop. Backtraces, locals and stepping use views internally; immutable reply owners retain their data. Measure allocations and latency at the stop as well as ingestion. Formatting may still allocate its output.
  • Memory is accounted. Each image knows its byte size per table; info modules (or a timings field) reports it, and the session's total is a budgeted number.

Test that a batch whose loads finish in any order, or partly fail, registers the same modules with the same IDs, and cover an unload/reload at the same address and exec. The simulator prepares images outside its world and keeps loading through its deterministic edge; no clocks, pool threads or filesystem accesses enter a world. Preserve Program reuse, post-mortem sessions and the vDSO bytes path. P6 changes run control, so it requires just stress and just sim 600.

Design

Observability: one instrumentation pass, many readers

Two kinds of engineers will profile uscope: people, who read timelines and flame graphs, and coding agents, which read text, parse JSON, and diff numbers but cannot look at a GUI. The code is instrumented once. Every span and counter feeds several outputs from the same pass, so neither reader needs instrumentation of its own and the two never disagree.

The rule: no one-off eprintln! timers. A new phase gets a span when it is written; an investigation starts from a timings report, a text profile, or a trace; a claimed improvement shows up in just bench --compare.

M1

Instrument once

  • An in-crate profile module: span! for phases and units, count! for per-thread integer counters (DIEs, bytes, rows, units, cache hits). It is compiled into every build, debug and release.
  • Spans never go around single DIEs or rows: a tracing span costs about 40 ns with a registry, and an enabled per-iteration Tracy zone produced 134 M zones in 2 s. Hot loops bump counters that are flushed once per unit.
  • Measure wall and thread CPU time for synchronous spans; worker metrics sum CPU work, not elapsed time. Peak RSS is process high-water, not a subtractable per-span counter. Attribute allocations explicitly: process totals in an isolated load, optional worker/span counters, live bytes tracked through cross-thread frees and reallocations without allocator recursion. This allocator needs its own narrowly documented unsafe implementation.
  • Instruction counters exclude kernel/hypervisor execution and do not inherit into the debuggee. Scope them to loader workers and report enabled/running time plus unavailable or multiplexed status. Never silently replace an unavailable counter with zero. Use explicit flow/dependency IDs for a critical-path report; nested timing spans alone cannot reconstruct a parallel DAG.
  • Cap trace buffers and dynamic labels; report dropped events. Disabled instrumentation must avoid clocks, allocation and input-dependent formatting. Simulation recording stays outside deterministic world state. Flush reports on both load success and failure, and distinguish foreground load, cache validation and background write time.
  • Keep one global allocator definition per binary. Define feature composition so the existing --all-features gate still compiles: system-alloc selects System over mimalloc, counting wraps the selected allocator, and optional Tracy reporting wraps it once. Compile default/all-feature/release combinations and exercise disabled tracing without profiler threads or sockets.
  • Sinks are chosen at run time (--timings, the flight recorder in debug builds) or at build time (the tracy feature). Adding a sink never means touching the instrumented code.
M2

Machine-readable first

  • uscope --timings FILE writes JSON: a schema version, a summary, counters per phase, and a traceEvents array in Chrome trace format. The trace part opens unchanged in ui.perfetto.dev, and trace_processor can query it with SQL.
  • just timings FILE [FILE] prints a compact text summary of one report, or the differences between two. --threads adds per-worker busy time, the longest unit, and the critical path.
  • Reports are stable: sorted, fixed column order, at most about forty lines by default with --all for the rest, and absolute numbers alongside percentages. That makes them diffable by a script and readable in a terminal or by an agent without paging through megabytes of trace.
M3

Deterministic regressions

  • just bench ingests a pinned corpus: the golden programs, the C++, Go, Zig, and tokio fixtures, and one large program, uscope's own debug build at a pinned commit. It runs each at jobs = 1 and at jobs = N.
  • Run one load per benchmark process, at jobs=1 and N, recording allocations, peak heap/RSS, retained bytes, per-table sizes, CPU time and wall median/spread. A deterministic toy instruction loop does not prove whole-loader reproducibility: allocator state, hash seeds, CPU dispatch, compiler and dependencies matter. Calibrate noise on the actual corpus and record hardware, flake.lock, Cargo.lock, profile, features and fixture hashes.
  • just bench --compare BASE compares saved reports with matching provenance, or builds an explicitly requested revision in an isolated checkout. Gate only calibrated instruction/allocation increases and resource ceilings, not improvements. Hardware perf counts are optional and machine-specific; use a pinned Callgrind lane if deterministic instruction gating is needed. Exact bytes gate determinism for identical inputs/implementation, not all future revisions.
  • Separate a small seconds-long smoke corpus from full large-program/counter/profiler runs. Run all corpus sweeps under scripts/contained.sh. Add only the stable smoke lane to just all; unavailable optional counters report a skip, while a dedicated counter CI job requires them. Baseline changes carry before/after evidence, never silently absorb a regression.
M4

Profilers as recipes

  • just profile-instructions PROGRAM: a release build with line tables under Callgrind, printed with callgrind_annotate --inclusive=yes --tree=calling and trimmed to uscope's frames. This is how the type builder and the double TypeIndex build on this page were found.
  • just profile-heap PROGRAM: a system-alloc build under DHAT, since Valgrind cannot see mimalloc, grouped by first uscope frame by count, bytes, and bytes live at peak. This promotes the script behind the allocation table on this page.

  • perf and valgrind join the default dev shell; perf is missing today. Gungraun (formerly iai-callgrind) could add Callgrind benchmarks later, but its runner must match the library version exactly and is not in nixpkgs.
M5

Tracy, for people

  • The optional tracy feature mirrors spans and counters to Tracy. Treat tracy-client =0.18.4, sys 0.28.0 and viewer 0.13.1 as the probe's candidate combination, not a permanent compatibility claim. Pin and compile the exact client/sys/viewer tuple in the profile shell and verify a captured trace before accepting it.
  • Build it with default-features = false plus enable, ondemand, and only-localhost. Leave out sampling and system tracing, which open inherited perf events that would follow the debuggee. Leave out the crash handler, which installs fatal-signal handlers, and broadcast, which sends UDP announcements.
  • tracy-alloc wraps mimalloc in ProfiledAllocator to show memory per zone.

Keep P0's instrumentation small: phase counters, bounded events and a machine-readable report. Reassess an existing tracing adapter before maintaining a general profiler framework. Nanosecond costs in the probe are configuration-specific; measure disabled overhead and enabled whole-load overhead. Tracy is optional and follows its documented feature controls.

Plan

Phases and tracking

Each phase is independently reviewable and leaves supported workflows working. Use these rules:

  • Preserve a reference, outside the tree. P0 adds a dump command that prints every public answer in a canonical text form, and builds the P0 commit once, in a worktree, as a pinned reference binary. Differential tests compare the new loader's dumps with the reference binary's, so no old loader code or model types stay compilable for the oracle's sake, and each family's old code is deleted as it migrates. Do not freeze known bugs into the oracle: a discovered correctness bug gets a failing test and separate correction. Small measured fixes are allowed when they stand on their own.
  • Prove a vertical slice. P1 builds the format and validation with lines first, in owned storage and jobs=1, then proves identical parallel output. It builds only the ingestion stages lines need; the per-unit DIE batches arrive with functions in P2.
  • Explicit adapters. During P1–P3 retain only adapters needed by the legacy variable/coroutine loader. List them and their deletion phase. Production must not run two full loaders indefinitely.
  • Actual dependency order. Lines need unit/file context and executable-range filtering; stripped Go lines need pclntab function completion. Functions contain generic/coroutine links supplied later. Types depend on scopes and origin resolution as well as strings. P4 removes the last adapters only after these cross-family dependencies are ported.

During migration, report temporary duplicate work and memory separately; keep the 1 GiB test cap. Differential runs compare dumps, so a test never holds the old and new graphs at once. New regression tests fail before their fixes; run focused checks while iterating and just all before commits, adding just sim 600 for lifecycle/model changes as required. All project commands run through the pinned shell, e.g. just dev --command just all. Status: todo doing done.

Testing

Keeping it correct while it moves

  • Equivalence. The pinned reference binary's dumps are the oracle until P4.4. Compare all observable fields, error/partial states and query results, not just names or node counts. Canonicalize graph references with cycle-aware stable correspondence; never use the new interner to normalize the oracle's answers. Ignore only documented storage multiplicity, preserving scope/type distinctions, ambiguous candidates, declaration provenance and row ordering. Include queries at boundaries and interiors. Known semantic corrections land with separate failing tests.
  • Determinism. Compare canonical payloads across jobs=1/2/max, fresh processes, reordered completion, copied input paths and rebound module IDs. Compare cache hits to cold ingestion. No timing/stat/path metadata enters the payload hash. If the simulator fingerprint gains payload identity, version its fingerprint format explicitly and keep golden executable manifests unchanged.
  • Owned reads. Synchronized rewrites and truncation of an input during its read produce a retry or a typed changed-input error, and retry exhaustion is explicit. Validation and views agree for images of 0, 1, a page minus one, a page and a page plus one bytes; wide-offset arithmetic is tested synthetically without allocating gigabytes.
  • Untrusted input. Existing dwarf-expression, elf-symbols and gopclntab fuzzers cover components, not the complete DIE loader. Add a bounded structured ELF/DWARF ingestion target and an image-validator target. Corrupt tags, counts, strides, offsets, spans, indexes, strings, cycles and checksums. Recompute the checksum for semantic corruption cases so they reach the validator. Synthetic limits exercise overflows without enormous allocations. All fuzz/sweep runs use scripts/contained.sh.
  • Behavior. Start from tests/debugger/{metadata,identities,debug_files,variables,values,execution,stepping}.rs, Go/tokio suites and the pure Go visibility test. Add only missing semantic cases: wide fields, recursive/nominal types, overlapping ranges, default/alternative locations and multiple expression contexts. Preserve GCC/Clang, optimization, PIE/frame-pointer coverage and synthetic malformed metadata. P6 additionally needs cleanup, cancellation, event/state consistency, just stress and just sim 600.
  • Cache. ScratchDir tests cover same-build-id modifications, same-size/mtime rewrites, normalization-version changes, executable relocation, distinct image bindings, separate-debug search changes/appearance, corrupt/truncated images, checksum-valid malformed indexes, symlinks/permissions, concurrent writers, eviction races, full/read-only storage and failed writes. Use observable synchronization, never sleeps or negative time-window assertions.
  • Resources. Use low loader jobs under nextest and a small parallelism lane. Keep cold correctness and warm-cache tests explicit, the global 1 GiB heap cap intact and OS containment around corpus runs. Account for all workers and held snapshots, not just the caller's allocations.
  • Performance. A seconds-long smoke benchmark joins just all and gates only deterministic counts (allocations at jobs = 1 and payload bytes), never wall time; full corpus runs and profilers are separate. Pin artifact hashes and provenance; review baseline increases with evidence.

Ideas

Further out, each with what we know

I1

Reuse units across rebuilds

After a one-line edit to the tokio server, 0 of 119 units were byte-identical: relinking moves every address. With address attributes ignored, 85 units (58% of the bytes) matched, and the rest differed only in addresses embedded in location expressions. Reusing unit batches across builds would need address-relocatable batches and fingerprints that ignore addresses. This becomes interesting once cold ingestion is near its floor.

I2

Ingest before anyone asks

uscope web and DAP sessions already know the program's path. They could watch it and re-ingest in the background as soon as the build rewrites it, so the image is cached by the time the user restarts. RAD Debugger pre-converts the debug info of libraries next to the program for the same reason.

I3

Abbreviation-specialized decoding

Profile abbreviation/form distributions before specializing decoding. LEB128, indirect, block and string forms are variable-width, so constant attribute offsets are valid only for a proved fixed-width prefix. Keep gimli as the reference and preserve malformed-input handling; defer a custom decoder until a measured bottleneck justifies it.

I4

Tables in the browser

The web page could receive the symbol and name tables as typed arrays and search them locally: fuzzy "go to function" with no round trip, from the same bytes as the cache.

I5

Huge pages, prefetch and search layouts

For images of hundreds of megabytes, madvise(MADV_HUGEPAGE) on the buffer, software prefetch in index builds, and Eytzinger-ordered search keys may cut TLB and cache misses. Apply only with counters showing those misses.

I6

Shared caches

A future distribution cache needs authenticated provenance, compatibility policy and an immutable transport/storage contract. A checksum-valid image can still lie about its source. Import into owned storage or a privately published local entry; never assume an arbitrary shared directory is immutable.

I7

Map private cache files

Mapping a cached image instead of reading it saves one copy, about a millisecond per 12 MB, since validation touches every byte either way. It is sound only for privately published cache inodes that no writer ever rewrites in place: a mapping reflects a later pwrite (R1). It would bring an unsafe module, rename/unlink lifetime tests and compile_fail tests that views cannot outlive the mapping. Worth it only if P5's timings show the copy on the cached critical path.

I8

Load modules asynchronously

P6 keeps the controller waiting while a batch of modules loads, as it waits for each module today. Loading behind a generation-tagged barrier would keep it serving requests meanwhile, at the cost of a new state machine: completions tagged by session, exec and mapping generation, deferred requests revalidated against their stop, and cancellation on exec, detach and shutdown. Consider it only if P6's stop-path timings show cold module loads still hurt with the cache.
