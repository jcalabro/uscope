uscope plan

Every system call, at a price production can pay

strace answers "what is this program asking the kernel to do?" by stopping the program twice for every call, which costs 28 to 155 times its runtime on syscall-heavy work (measured below). This plan gives uscope two engines behind one event model. An eBPF engine, with small C programs that uscope loads through Rust's aya, watches any process for a few tens of nanoseconds per call and never stops it. A ptrace engine, which uscope already has the controller for, is exact and synchronous: it catches, stops on, and tampers with calls in programs uscope debugs. The CLI speaks strace's language. The web UI turns the stream into tables, heat maps, and timeline lanes beside the profiler's samples.

The work ships in seven phases (Phases). The ptrace engine comes first because the controller already sees syscall stops and currently rejects them (src/backend/linux.rs:2169). The BPF engine follows: counting first, then streaming, then production attach. The CLI and web UI grow with each engine rather than at the end.

Goals

What this has to do, and what it will not

G0

Safe by default; never breaks production

Every default favors the traced system over the trace:

  • When BPF cannot load, uscope fails with a clear explanation. It never quietly falls back to an engine that stops the target.
  • The ptrace engine runs only when asked for by name.
  • Nothing ever changes a syscall.
  • Ring, budget, and string sizes are bounded from the start.
  • A slow uscope loses data and says so; it never slows the target to keep up.
G1

Run in production

Trace a live service without stopping it, injecting code into it, or adding more than tens of nanoseconds per traced call. Count mode adds no work per event in uscope. Overhead is a measured, checked number, as for the profiler.

G2

Everything strace does that people use

Filters by name, class, regex, status, path and fd; decoded arguments with fds shown as paths and sockets; timing in all of strace's forms; -c summaries; following forks; stack traces; attaching to a running process.

G3

More than strace can

Latency distributions per call rather than averages; calls each thread is blocked in right now; syscalls on the same timeline as CPU samples and off-CPU time; call sites symbolized to source by the debugger's own debug info; catchpoints that stop in the debugger.

G4

Never a convincing wrong answer

Lost events, truncated strings, arguments read after the call, unreadable memory, invisible vDSO calls, and io_uring work are all shown in the output. Nothing is dropped or guessed without saying so.

G5

One model, two engines

Both engines produce the same neutral events, so decoding, filtering, statistics, CLI output, captures and the web UI are written once. The ptrace engine is also the oracle the BPF engine is tested against.

N1

Not in scope

A security monitor (Falco, Tracee), a policy engine, or tracing the whole machine: there is always a named program, pid, or cgroup. Nothing changes syscalls either. strace's -e inject and -e fault are out of scope for both engines. ltrace-style library tracing and io_uring operation tracing are deferred.

Landscape

What exists, and what to take from it

T1

strace 7.2

ptrace with PTRACE_O_TRACESYSGOOD and PTRACE_GET_SYSCALL_INFO, plus hand-written decoders for nearly every call and structure.

Take: the filter language (-e trace=%file,!close, status=failed, -P), the output format people can read without thinking, and -c/-C/-w/-S/-U.
Avoid: stopping on every call; <unfinished …> interleaving as the only way to see concurrency; an average as the only latency.
T2

perf trace

Tracepoints into a ring; its augmented_raw_syscalls BPF program copies pointer arguments. A per-syscall map filled from BTF says what to copy: a string, a struct of N bytes, or a buffer whose length is argument N.

Take: the argument-spec table driving one generic BPF copier, instead of one BPF program per call.
Avoid: reading at entry only and silently leaving failed reads undecoded.
T3

bpftrace, bcc syscount

Aggregation in kernel maps: counts, log2 latency histograms, nothing per event leaves the kernel.

Take: count mode as a first-class mode, and log2 histograms as the unit of latency.
Avoid: one-off scripts; pid filters that only catch the first process.
T4

sysdig, Falco, Tracee

Production syscall capture with eBPF, containers and Kubernetes metadata, capture files you can replay.

Take: per-container targeting by cgroup, recordings you can reopen, privileged DaemonSet deployment.
Avoid: system-wide capture as the default; their io_uring blind spot, which they do not show the user.
T5

gdb catch syscall

Stops in the debugger at entry and exit of named calls.

Take: catchpoints, conditions on them, and the ability to inspect and change arguments at the stop.
Avoid: PTRACE_SYSCALL on every call when only one is caught. A seccomp filter avoids it.
T6

lurk, intentrace (Rust)

Readable strace clones: color, JSON output, plain-language annotations.

Take: color by outcome, an ndjson mode for scripts.
Avoid: a ptrace-only design.

M1

Read pointers at exit

A workload opened a path stored in a file-backed page it had mapped but never touched. Over 1000 calls, bpf_probe_read_user_str failed every time at entry and succeeded for all 2002 opens at exit. The kernel had faulted the page in to do the call. The strace engine does not have this problem.

M2

Store little at entry

Copying a 400-byte record into a per-thread hash at entry cost 12 ns more per call when counting, and 41 ns more when streaming, than storing only a timestamp. The argument registers are still in pt_regs at exit; only orig_ax holds the number, since ax holds the result by then.

M3

The tax is real but small

On the file workload, an attached tracepoint slows untraced processes by 18%. On a host making 1 M calls per second, that is about 3% of one core. For production, fentry on a short list of syscalls removes it entirely, and the UI says which attach mode is in use.

Architecture

Two engines, one stream

engine · bpf

Kernel programs

Attaches tp_btf on entry and exit, or fentry/fexit for short lists, plus sched_process_fork/exit. Filters by tgid set or cgroup and syscall bitmap. Counts into per-CPU maps, and streams compact records into a ring.

no stops
engine · ptrace

Controller thread

Installs a seccomp RET_TRACE filter for the chosen calls at launch. Classifies syscall stops, reads them with PTRACE_GET_SYSCALL_INFO and process_vm_readv, then resumes or publishes a catch stop.

synchronous
src/backend/linux/syscalls

Edge decode

Ring records and ptrace stops become neutral SyscallEvent batches with raw words, captured byte blobs, and their capture state.

reader thread
src/syscalls

Enrich (pure)

Tracks fds to keep a path and socket table per process, and the process tree from forks and execs. Applies filters and folds statistics. Adds symbolized stacks from the profiler's symbolizer.

pure, tested
src/capture

Store

New tables in the existing capture container: calls, blobs, statistics, processes, fds, gaps. One file can hold syscalls and CPU samples on one clock.

append-only
src/present · cli · web

Show

One formatter for strace-style lines, shared by the CLI, DAP console and web. The web queries the capture for tables, heat maps and lanes.

shared

Threads. The BPF engine needs no ptrace and runs beside the debugger as the profiler does, on its own reader thread with a fixed ring. The ptrace engine runs entirely on the controller thread that owns the tracee, as AGENTS.md requires. Syscall stops are classified there like any other wait event.

All-stop. A syscall stop that only records a call is handled inside the controller: record, then resume. It is never published, in the same way a breakpoint whose condition is false is not. Only a catchpoint publishes a stop, with a new StopReason::Syscall { phase, call } that carries a StopId like every other stop. While stopped, the BPF engine's timings for that thread include the stop. Such calls are marked "spanned a debugger stop" so a stop never looks like a slow syscall.

One clock. BPF records bpf_ktime_get_ns (CLOCK_MONOTONIC). The profiler's perf events use USE_CLOCKID with the same clock, so syscall spans and CPU samples line up without conversion.

Event model

Neutral types, explicit gaps

// src/syscalls/model.rs — no ELF, BPF, or ptrace types here.
pub struct SyscallId { abi: Abi, number: u32 }          // Abi::X86_64 | X86_32 | X32
pub struct SyscallEvent {
    thread: ThreadId, process: ProcessId,
    call: SyscallId,
    args: [u64; 6],                                       // raw words, always
    captured: SmallVec<[Capture; 2]>,                    // bytes behind pointer args
    outcome: Outcome,
    entered: Option<Instant>, exited: Option<Instant>,   // either may be unseen
    stack: Option<StackId>,
    flags: EventFlags,                                    // SPANNED_STOP, ENTRY_UNSEEN, ABI_UNCERTAIN …
}
pub enum Outcome { Returned(i64), Failed(Errno), Unfinished, ProcessExited, Unavailable }
pub struct Capture { arg: u8, when: ReadAt, state: CaptureState, bytes: BlobRef }
pub enum ReadAt { Entry, Exit }                           // exit reads may postdate a racing write
pub enum CaptureState { Complete, Truncated { wanted: u32 }, Unreadable, NotRequested }
pub struct SyscallStats { calls, errors_by_errno, total_ns, max_ns, log2_ns: [u64; 40], bytes }

Syscall tables. src/syscalls/table.gen.rs lists names and numbers for each ABI. It is generated from the kernel's syscall_64.tbl and syscall_32.tbl. A test fails when it is stale, as protocol.gen.ts does. Argument specs say what each argument is, and they drive both engines:

  • fd
  • C string or path
  • a buffer whose length is argument N
  • a buffer whose length is the return value
  • a struct of a fixed size
  • sockaddr with length
  • iovec array
  • flags, by name of the flag set
  • pid, signal, or mode

Specs are generated from SYSCALL_DEFINE prototypes and then corrected by hand. Classes (%file, %net, …) come from the same specs. They are not copied from strace, whose sources are LGPL.

Never guess. If the BPF side cannot read a string, the event says Unreadable and the CLI prints 0x7ffd… <unreadable>. A call whose exit arrives without its entry is ENTRY_UNSEEN, with no duration; that happens when tracing starts mid-call or seccomp rejected the call. A ring overflow is a gap with a count on the thread's timeline. Statistics show "≥" whenever a gap overlaps their range.

The BPF engine

Watch anything, stop nothing

B1

Modes

  • count: per-CPU maps keyed by (tgid, call), holding count, errors by errno, total and max ns, a log2 histogram, and bytes for I/O calls. Nothing goes through the ring. This mode is -c.
  • stream: count, plus one ring record per selected call.
  • in flight: a per-thread entry map that userspace scans every 100 ms. It shows which call each thread is blocked in right now, and for how long, without waiting for the exit.
B2

Attach

The default is tp_btf/sys_enter and sys_exit. When the selection has at most 32 syscalls and all of them have BTF functions, uscope uses fentry/fexit on just those, which removes the system-wide tax. Which mode it chose, and why, goes into the capture's accounting.

B3

Which processes

A tgid hash, seeded before the target runs. uscope launches the child behind the profiler's pre_exec gate, so no call escapes. sched_process_fork adds children when following, and sched_process_exit removes them. Alternatively a cgroup id selects a container or systemd unit. Pids are translated into the target's namespace with bpf_get_ns_current_pid_tgid.

B4

Arguments

At entry the program stores only a timestamp. It keeps the timestamp in task storage, which needs no cleanup when a thread dies. At exit one generic copier reads the selected call's pointer arguments, following the argument spec table. Strings are bounded by -s; buffers, sockaddr, and the first k iovecs are bounded too. Every copy is marked ReadAt::Exit. execve's arguments are read at entry, since the old memory is gone at exit. sched_process_exec supplies the new image.

B5

Records

Records are variable-length: a fixed 80-byte header (tid, call, entry time, duration, return value, six arguments), then the captured blobs. A failed reserve increments a per-CPU loss counter. Losses become gaps with counts, and the UI shows them. Ring size and drain interval are fixed at start. M1 and the 54% loss above show why record size is part of the design.

B6

Stacks

-k takes a frame-pointer user stack with bpf_get_stack, interned in a stack map. Where frame pointers are missing, -k=dwarf copies the top of the user stack (up to 8 KiB) for selected calls only. The profiler's unwinder and symbolizer then turn it into source lines, with truncation shown as it is for samples.

B7

Compat and odd ABIs

Compat calls are recognized exactly by reading thread_info.status & TS_COMPAT through CO-RE, which covers 32-bit processes and int 0x80 from 64-bit ones. They are named from the ia32 table. The relocation was tested; a 32-bit fixture tests the result (Y3.4). x32 calls are recognized by bit 30. On a kernel whose BTF lacks the field, bpf_core_field_exists fails, and those calls are flagged ABI_UNCERTAIN rather than guessed.

BPF programs

Small C programs, built by clang, loaded by aya

The kernel side is a handful of C programs, a few hundred lines in all. They are compiled to BPF objects by clang and embedded in the uscope binary. At run time uscope loads them with aya, a pure-Rust loader that needs no libbpf and no C library, and attaches them and reads their maps. Everything the programs produce is decoded and interpreted in Rust. The C does as little as possible: filter, timestamp, copy bytes, count.

Everything below was built and loaded on this machine, with the pinned nixpkgs, in a privileged container.

P1

Layout

  • src/backend/linux/syscalls/bpf/syscalls.bpf.c holds the entry, exit, fork, exit-of-process and exec programs.
  • kernel_types.h declares only the kernel fields the programs read, each with preserve_access_index. It is written by hand, and no generated vmlinux.h is checked in.
  • records.h holds the ring records and map values, which Rust decodes.
P2

Build

build.rs runs the flake's llvmPackages.clang-unwrapped with these flags:

  • -target bpf -O2 -g
  • -Wall -Werror -nostdinc
  • -fdebug-prefix-map

The only include paths are libbpf 1.7's BPF headers and nixpkgs' Linux UAPI headers. The flake exports both as USCOPE_BPF_CLANG and USCOPE_BPF_INCLUDE. Outside the dev shell the build fails and names the missing variable; it never falls back to the host's tools.

A compile takes 0.08 s, and rebuilding gives a byte-identical object (measured). The unwrapped compiler matters: nixpkgs' cc-wrapper adds host flags and warns on -target bpf.

P3

CO-RE

Every field access in the programs is relocated by aya against the running kernel's BTF, so one object runs on every kernel.

  • Tested. kernel_types.h was written with the fields deliberately misordered and mis-padded. tgid and pid read through BPF_CORE_READ still matched the helper's values 3,000,044 times out of 3,000,044, and so did pt_regs->orig_ax.
  • bpf_core_field_exists lets a program check whether a field exists. A program does that before relying on a field, and reports an absent one rather than reading garbage.
P4

Maps

  • A hash of target tgids, filled by fork and exit tracepoints.
  • Task storage for each thread's entry timestamp. It needs no cleanup when the thread dies, and costs 25 ns per call less than a hash. aya creates it once allow_unsupported_maps() is set; tested.
  • Per-CPU arrays for statistics and loss counts.
  • A ring buffer for records.
  • An array for configuration.
P5

The Rust side

src/backend/linux/syscalls/bpf.rs holds no unsafe. Map values are byte arrays ([u8; N]), which aya already accepts, and they are decoded with zerocopy structs. A loader written this way built under forbid(unsafe_code).

A test reads each record's layout from the object's own BTF and compares it with the Rust struct, size and every field offset. C and Rust therefore cannot drift apart silently.

P6

Review and safety

The verifier proves at load time that the programs terminate and touch only memory they are allowed to. The C code is kept within that envelope and small enough to review line by line:

  • no tail calls
  • bounded loops only
  • per-CPU scratch space for anything larger than 512 bytes

A load failure prints the verifier log to the flight recorder, along with the name of the kernel.

P7

What the kernel allows

  • Fedora 44 turns CONFIG_FUNCTION_ERROR_INJECTION off, so bpf_override_return and fmod_ret on syscalls are unavailable. BPF cannot change a syscall's result, and uscope never changes syscalls anyway.
  • Zero-argument syscalls have no BTF function, so fentry cannot attach to them.
  • Linux 7.2's sleepable syscall tracepoints (tp_btf.s) are rejected by aya 0.14, and by libbpf 1.8 as well.
P8

Privilege

As a normal user here, the first map creation fails with EPERM, because unprivileged_bpf_disabled is 2. tp_btf needs only the world-readable /sys/kernel/btf/vmlinux, not tracefs, which is root-only here. uscope probes before loading and names the missing capability instead of passing EPERM along.

The ptrace engine

Exact and synchronous, for the debugger

uscope's controller already sets PTRACE_O_TRACESYSGOOD (src/backend/linux/native.rs:1072), classifies the stop (signals.rs:311), and rejects it. This engine turns that rejection into a feature. It is the right engine when uscope is already debugging the target, since a process can have only one ptrace tracer and strace cannot attach alongside uscope. It is also the only engine that can stop at a call, which is what catch syscall needs. It needs no privilege beyond debugging. It is also the oracle the BPF engine is tested against. It runs only when chosen by name, with --engine ptrace or by a catchpoint in a debugging session.

  • Launch: the pre_exec hook installs a seccomp filter. The filter returns RET_TRACE for the chosen calls and RET_ALLOW otherwise, so calls that are not chosen run at full speed (measured above). After an entry stop, PTRACE_SYSCALL takes the thread to its exit stop.
  • Attach: a running process cannot be given a filter from outside. Attaching means stopping at every call, at about 5 µs each. uscope refuses unless the user also passes --stop-every-call, and says why.
  • Reading: PTRACE_GET_SYSCALL_INFO (5.3) gives entry, exit, or seccomp stop, plus arch, number, arguments, and return value. Memory is read at entry with process_vm_readv, so paging is not a problem.
  • Catchpoints: catch syscall openat [entry|exit] [if EXPR]. Conditions are evaluated by the existing expression evaluator, with $arg0…$arg5, $ret, and $path bound.
  • Detaching: a seccomp filter cannot be removed, so after detach the chosen calls fail with ENOSYS. uscope therefore installs the filter only on processes it launched and will kill on exit. On any other detach it refuses unless told --detach-anyway. strace documents this in its BUGS section and lets it happen.

Where formatting lives. Formatting goes in src/present/syscalls.rs and is shared by the CLI, the DAP console, and the web UI, as AGENTS.md requires. It covers errno names and messages, flag sets, sockaddr for inet, inet6, unix and netlink, stat, iovec, msghdr, signals and siginfo, clone flags, mmap protection and flags, and common ioctl numbers. Decoders are pure functions from (spec, raw words, captures) to tokens. The CLI colors the tokens; the web turns them into spans with tooltips.

fd table. -y and -yy are answered from a per-process table. It is seeded from /proc/PID/fd and /proc/PID/net/* at attach, and kept current by tracking the calls that open, dup, and close fds, including accept, socket, pipe2, dup3, fcntl(F_DUPFD), and close_range. An fd whose origin was not seen shows as 3<?>, never a stale path. If the trace has a gap, the table is reseeded from /proc, and that reseed is noted.

Fuzzing. The record decoder and every structure decoder get a fuzz target, using the existing fuzz/ pattern.

CLI

uscope syscalls: strace's flags, uscope's engines

The command is named for the data it collects, as the REPL's syscalls command and the web UI's Syscalls tab are. That leaves trace and traces free for distributed tracing later (D7). The flags follow strace's, so the strace muscle memory carries over without the name promising exact compatibility.

# a launched program and its children, through BPF; fails with an explanation without CAP_BPF+CAP_PERFMON
uscope syscalls -e trace=%file,%net -yy -T -- ./server --port 8080
# strace -c, measured in the kernel; -w for wall clock; latency percentiles beyond strace
uscope syscalls -c -S p99 -p 4182 --duration 30s
# production: one container, a short list (fentry, no system-wide tax), recorded for the web UI
uscope syscalls --cgroup /sys/fs/cgroup/system.slice/app.service -e trace=openat,connect,fsync -o app.usprof
# no privilege: the ptrace engine, by name, with a seccomp filter for just these calls
uscope syscalls --engine ptrace -e trace=openat,connect -- ./tool
# scriptable
uscope syscalls --format ndjson -Z -- make -j8 | jq 'select(.errno=="ENOENT") .args.path'
# syscalls with CPU samples in one capture
uscope record --syscalls %file,%net --preset prod -- ./server

Other entry points.

  • uscope report FILE gains a syscall summary when the capture has one.
  • In the debugger REPL:
    • syscalls start|stop|summary|inflight
    • catch syscall NAME… [entry|exit] [if EXPR]
    Each is added to COMMANDS in src/cli/commands.rs, with highlighting and completion of syscall names and classes.
  • DAP gets catch syscall as an exception-breakpoint filter.

Output order. The BPF engine prints calls in exit order. There is no interleaving, because entry and exit arrive together. Calls still running past --in-flight (default 1 s) get an "in flight" line, which is the honest version of strace's <unfinished …>.

Web UI

Where did the time go in the kernel, and why did it fail

W1

Summary table

Virtualized and sortable, with every -c column plus p50, p90, p99, max, bytes, and an errno breakdown that expands per row. "Group by" can be syscall, class, process, thread, fd/path, or call site.

W2

Rate over time

Stacked calls per second by class or by syscall, with errors overlaid as a red line. Dragging a range filters every other view.

W3

Latency heat map

Time across, log2 latency up, color by count, as in Gregg's latency heat maps. Bimodal latency, cache hit against miss, shows up at once. Clicking a cell lists its calls.

W4

Histograms and errors

A log2 histogram per syscall, with the selection overlaid on the whole. Error bars by errno for each syscall. "Top callers" ranks the call sites behind slow or failed calls, using stacks symbolized by the debugger.

W5

Timeline lanes

A lane per thread shows syscall spans, with blocking calls hatched and failed calls as red ticks. Each lane sits under the profiler's CPU and off-CPU lanes on one clock, so "off CPU for 40 ms" lines up with the fsync that caused it.

W6

Event log

Every call, virtualized, formatted by src/present, and filtered by the same syntax as the CLI. A row expands into decoded arguments, hex dumps, its stack, and a link to the call site in the source view.

W7

Files and network

Built from the fd table. Files are listed by path, with opens, failures, bytes read and written, and fsync time. Network shows endpoints, connects with their outcome and latency, and bytes each way.

W8

Processes and in flight

A fork and exec tree with each process's counts, exit status, and lifetime. While live, a table shows what every thread is blocked in right now, and for how long, read from the in-flight scan.

Plumbing. The server is a DebuggerHandle client, as it is today. Syscall captures are profiles to the web server (src/web/profiles.rs), keyed by digest, republished every 2 s while recording. New requests go in src/web/protocol.rs (ts-rs): syscallSummary, syscallRate, syscallHeatmap, syscallHistogram, syscallLog (paged), syscallFiles, syscallNetwork, syscallProcesses, and syscallInFlight. Bulk columns travel as the binary frames connection.rs already supports. Answers are cached by request against the capture revision.

Drawing. There is no chart library. The heat map, rate chart, and lanes are canvas, sharing web/src/profile/paint.ts; histograms and tables are DOM. Colors are the plan tokens: one hue per class, a sequential ramp for the heat map, and red only for errors. Everything works in both themes. The URL holds the filter, range, grouping, selected row, and tab. A live debugging session also gets a Syscalls panel fed by the ptrace or BPF engine.

Production

Guarantees, not intentions

S1

The target

  • The BPF engine runs no code in the target. It sends no signals and takes no ptrace stops.
  • Its cost per traced call is measured, and the reference numbers are checked into bench/syscalls-overhead.json.
  • A slow reader loses records at the ring and counts them; it never stalls the target.
S2

Everyone else on the host

  • The default production recipe is a short syscall list, which uses fentry and costs nothing for other processes.
  • Tracepoint mode costs other processes about 33 ns per call. uscope prints that cost when it attaches, and records it in the capture.
  • --budget lowers what it captures when its CPU use crosses the budget, in this order: drop stacks, cap strings, sample, then count only. Each step is recorded.
S3

Privileges

  • The BPF engine needs CAP_BPF and CAP_PERFMON, never CAP_SYS_ADMIN.
  • Run it from a systemd unit with AmbientCapabilities= or a privileged DaemonSet. In containers, a BPF token (6.9+) works.
  • The docs warn against setcap on a shared host. Those capabilities let any user read any process's syscalls, and much of kernel memory.
  • The ptrace engine needs only what debugging already needs.
S7

Failing well

Before loading anything, uscope probes for the capabilities, BTF, the kernel version, lockdown, and each map and program type. Each missing piece produces one specific message with the fix, never a bare EPERM:

error: uscope syscalls needs CAP_BPF and CAP_PERFMON, and this process has neither.
  uscope uses eBPF so it never stops or slows the traced program, and it will
  not fall back to ptrace on its own. To continue, one of:
    - run it from a unit with AmbientCapabilities=CAP_BPF CAP_PERFMON
    - on NixOS or system-manager, import uscope's bpf module and run through
      /run/wrappers/bin/uscope-bpf (docs/syscalls.md#privileges)
    - trace a program you launch with --engine ptrace, which stops the
      program at each chosen call
S4

Kernels

  • The BPF engine supports Linux 5.15 and newer, with BTF. Every map and program type it uses is present there, task storage included, so there are no fallback paths.
  • A feature probe at start records what the kernel offers:
    • task storage
    • fentry for each chosen syscall
    • bpf_get_ns_current_pid_tgid
    • sleepable tracepoints
  • An older kernel, or one without BTF, fails with the reason. Tests run only on the host kernel; CO-RE, the feature probe, and these errors cover the rest.
S5

Continuous

uscope syscalls --continuous DIR --keep 24h reuses the profiler's sealed segments. In count mode a segment is one statistics snapshot per interval: kilobytes per hour. Triggers flush full-fidelity windows:

  • SIGUSR2
  • an SDK trigger
  • a syscall slower than a threshold
  • an errno
S6

Containers

Targets can be a cgroup, or a container id resolved to one. Pids and paths are shown in the target's namespaces. Paths resolve through /proc/PID/root, and module build ids identify binaries as they do for the profiler.

Decisions

Choices, with the alternatives

D1

Collection

ChoseneBPF and ptrace, behind one modelOnly eBPF is cheap enough for production. Only ptrace is exact and can stop at a call, and uscope already owns it. It is also the BPF engine's test oracle.
PassedeBPF onlyIt could not provide catchpoints or unprivileged tracing, and it would have no oracle to be tested against.
Passedperf_event_open tracepoints without BPFNo pointer contents, and it needs tracefs.
D2

BPF language

ChosenC programs built by clang, loaded by ayaThe kernel side is small and talks in kernel types. C has full CO-RE and every map type. Any clang builds it, with no linker and no tie to rustc. The Rust side stays free of unsafe code.
PassedRust with aya-ebpfIt needs bpf-linker built against exactly rustc's LLVM. nixpkgs' bpf-linker, on LLVM 21, failed to link the pinned nightly's LLVM 22 output. It has no CO-RE yet and no task-storage map, and every helper call is unsafe. Its performance was the same.
Passedlibbpf-rsIt adds libbpf as a C library dependency, generates unsafe skeletons, and brings a second build system. aya already loads C objects.
D3

Attach

Chosentp_btf by default; fentry/fexit for short liststp_btf covers every syscall and ABI. fentry removes the host-wide tax (measured).
Passedsyscalls:sys_enter_* tracepoints, kprobesSlower, need tracefs, and the per-syscall events miss compat calls.
D4

When to read arguments

ChosenAt exit, marked as such; execve at entry1000 of 1000 fresh-page reads failed at entry (M1).
LaterSleepable tp_btf.s at entryThe kernel has it as of 7.2; aya and libbpf do not load it yet (P7). uscope uses it once aya can load it; uscope does not change aya itself.
D5

Storage

ChosenTables in the capture containerOne file and one clock with CPU samples. Segments, the web UI, and recovery already work.
PassedA separate trace formatIt would duplicate everything above.
D6

CLI surface

Chosenstrace's flags and output, with explicit additionsPeople already know them, and scripts port over.
PassedA new syntaxNothing would gain from it.
D7

Command name

Chosenuscope syscallsIt names the data, as the REPL command, web tab, and capture tables already do. It cannot collide with OpenTelemetry's traces, and it extends naturally: libcalls for uprobes later, traces or otel for distributed tracing.
Passeduscope straceInstantly recognizable. But it promises exact strace behavior: every flag, every output byte, ptrace semantics. Each difference would then read as a bug, and the BPF engine never stops the target the way strace does.
Passeduscope traceIt is the word distributed tracing will want.
Passeduscope syscall, sys, snoopSingular reads like an action, "make a syscall". sys is vague, and snoop suggests one-off bcc tools.
Testing

The ptrace engine is the BPF engine's oracle

Pure units

Covers the filter parser, spec tables against the generated numbers, statistics folding, the log2 bucket edges, and fd-table transitions including close_range and dup3. Also seccomp filter generation, run through a userspace cBPF interpreter. Decoders and the record parser are fuzzed.

seconds
ptrace scenarios

Scenario fixtures in tests/fixtures/c/syscalls/ make known call sequences and print sync lines: a path that does not exist, a sockaddr to a local listener, fork and exec, threads blocked on a pipe, a path on an untouched page, and a 32-bit build. Tests cover catchpoint stops with StopIds, cleanup, and no surviving inferiors.

nextest
Dual-engine

The same fixtures run under both engines, and the decoded sequences must be equal per thread. They may differ only in fields marked as differing, such as ReadAt and durations. It needs CAP_BPF and CAP_PERFMON, so it is a separate test binary run by just test-bpf. That recipe runs nextest through /run/wrappers/bin/uscope-bpf when it exists. Otherwise it fails with the setup instructions; it never skips silently. Plain just test stays unprivileged, so the profiler's permission tests still see what users see.

privileged
Simulator

New conformance-pinned rules K-SYS-1 onward: entry and exit stops, GET_SYSCALL_INFO, seccomp RET_TRACE ordering. A model of the tracepoint stream feeds the real decoder and folder. An oracle checks that every call the simulated kernel served is either in the trace or counted as lost. Sabotage tests and coverage marks are included.

sweep
Overhead

just syscall-overhead runs the three workloads from Measurements plus the Go and tokio server fixtures, under each mode. Results are compared with bench/syscalls-overhead.json, as profile-overhead does.

minutes
Web

Vitest covers the heat-map binning and the formatting round trip. Playwright drives the tabs against a recorded capture. The replay transcripts include a syscall capture.

seconds / e2e
H1

Dev host setup, once

The flake exports nixosModules.uscope-bpf. It declares one security wrapper around env that carries cap_bpf,cap_perfmon. Only the owner and the wheel group can run it. Each host's own NixOS or system-manager configuration imports it, from dotfiles: this repo's dev shell cannot create a binary with file capabilities, and the nix store cannot hold one. The wrapper moves its capabilities into the ambient set before it runs its command, so they survive nix develop, contained.sh's systemd-run --scope, and nextest's test processes. That chain is to be verified once the wrapper is installed. No sudo, container, or VM is involved.

{ inputs, ... }: {
  imports = [ inputs.uscope.nixosModules.uscope-bpf ];
}
# declares, in effect:
security.wrappers.uscope-bpf = {
  source = "${pkgs.coreutils}/bin/env";
  owner = "root"; group = "wheel"; permissions = "u+rx,g+x";
  capabilities = "cap_bpf,cap_perfmon+ep";
};

Hosts without Nix get the same thing from docs/syscalls.md: a root-owned copy of env in /usr/local/libexec with setcap cap_bpf,cap_perfmon+ep, mode 0750, group wheel. Capabilities on a plain binary do not reach the programs it runs, so it also has to raise them to ambient; until uscope ships a tiny launcher for that, NixOS's wrapper is the supported path.

Y3.4—Losses include the kernel’s skipped program runsA preempted run makes the next one on its CPU skip. The count covers every process’s runs, so it bounds the loss rather than measuring it.

Deferred

Not now, on purpose

  • io_uring operations as syscall-like events, from the io_uring_submit_req and io_uring_complete tracepoints. Until then the UI flags io_uring use.
  • Sleepable entry reads (tp_btf.s), once aya loads them.
  • Library calls (ltrace) through uprobes, sharing this model.
  • Kernel stacks for slow syscalls; they need CAP_PERFMON, which BPF already has.
  • Rewriting arguments from BPF: never. It is unsafe and needs CAP_SYS_ADMIN.
Answers

Decided with the maintainer, 2026-10-12

  • Safe by default. Without privilege, uscope syscalls fails and explains; it never falls back on its own (G0, S7).
  • Privileged tests use a capability wrapper declared once in host configuration, with no sudo, container, or VM (H1).
  • No whole-host tracing. There is always a named target.
  • Children are followed by default (--no-follow).
  • Kernel floor is 5.15 with BTF.
  • No tampering: -e inject and -e fault are out of scope.
  • No kernel matrix. Only the host kernel is tested.
  • The ptrace engine ships first. Syscalls share the profiler's capture file. Text and ndjson output.

Still open (research, not a decision): does a call that seccomp rejects reach sys_exit without sys_enter? The kernel code suggests it does, but this was not tested. The model handles it either way (ENTRY_UNSEEN).
